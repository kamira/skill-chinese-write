## `.1` — 兩個列舉器都構造上走不到它

判準是 fable 給的,不是「哪個目錄好看」:

> **「skill」這個身分是由列舉器定義的**——誰列舉 `skills/`,誰就在定義什麼是 skill。

本 repo 有兩個列舉器:平台載入器列舉 `plugins/<p>/skills/*`(呼叫面),
治理閘列舉頂層 `skills/*`(治理面)。落地後兩者**都走不到** `engines/zh-style/`:

    頂層          skills/zh-style/        → 不存在
    出貨樹        plugins/*/skills/zh-style/ → 0 個(10 個孤兒已清)
    引擎單一真相  engines/zh-style/{scripts,assets,README.md}
    引擎出貨      plugins/<p>/engines/zh-style/ × 10

`SKILL.md` 隨遷改名為 `README.md`——**空殼仍是 skill**(codex),留著會被治理面判成
「缺 SKILL.md 的壞 skill」而不是「非 skill」(fable)。

### 施工中差點弄丟的東西:引擎的版號戳記

`SKILL.md` 的 frontmatter 裡有 `metadata.version`,主 agent 拿掉 frontmatter 時**連版號一起拿掉**,
而那條「引擎內容變了、十個宿主都要 bump」的紀律靠它。已保留在 `README.md`,並在檔內寫明
**frontmatter 不會讓它變成 skill,`SKILL.md` 這個檔名與 `skills/` 命名空間才會**。

### ① 唯一的 fail-open:補之前隱形,補之後點名,可證

**補之前**:`hosts_of` 從 `PLUGINS` 種席位、`skill_version` 用 `skills/{n}/SKILL.md`、
`tree_files` 只掃 `skills/` 前綴。引擎移出後**同時離開這兩個命名空間**,
「引擎內容變了、十個 plugin 出貨全變」它永遠看不見——而**本檔 docstring 自述要堵的洞,
舉的例子就是 zh-style**。

**補之後**(實跑 `--since 38b6643`):

```
plugin「architecture」的版號沒有遞增(entry 1.1.0 → 1.1.0),但它有 2 個變更理由:
PLUGINS 成分變了 (...) → (...);它打包的引擎「zh-style」內容變了——已安裝的使用者拿不到這些變更
```

十個宿主逐一點名。bump 完(十個 entry + 十個 plugin.json + marketplace 4.3.1 → 4.4.0)轉綠。
**這就是那一格從隱形變成可證的全過程。**

施工中另修兩件:

- **`GEN_SPACES` 補 `engines`**——否則引擎副本被算成「plugin 自己的手寫檔」。
  理由不實不是小事,**它會讓真正的手寫檔變更淹沒在噪音裡**。
- **「名冊不存在」與「名冊壞掉」要分開**——基準 commit 早於 `ENGINES` 引入,
  原本會紅在「名冊形狀變了,本閘失效」。那不是閘失效,是**引入新名冊的必然代價被誤判成缺陷**。
  舊 ref 沒有 = 當時沒引擎(誠實讀法);HEAD 沒有才是真的壞了。

### ③ 寄生錨點:解綁,而被寄生的那條斷言升格

`genres_table_check` 的 `--self-test` 拿 `$PY skills/zh-style/…/zh_style_check.py --self-test`
當 `ci_local.sh` 的**插入錨點**。引擎路徑一動它就紅在「錨點找不到」——**而它真的紅了一次**,
是 fail-closed 逼出來的修改,不是靜默。

解綁:受測判定是**全文字面子串比對**,插入位置無語意,改成**文末附加**,判別力一分不差。

但 fable 指出 codex 沒看到的一格:**原錨點順帶寄生了一條隱性斷言**——
「引擎的 self-test 在 CI 裡」(錨點找不到就紅)。解綁後它會蒸發。

> 它不該以副作用的形式存在(**斷言藏在別支閘的 self-test 副作用裡,
> 正是本案「宣稱在一處、實際在另一處」的形狀**),但也不該無聲消失。

已升格為具名斷言 `[引擎/CI]`:表列通用引擎的 lint 必須出現在 `ci_local.sh` 文本裡。
紅端實測可達(把 CI 裡那行改名 → 具名報錯)。

## `.3` — 單腿擋不住復發,所以是三腿加一

fable 復查現行閘後指出的洞:

> zh-style 只重現於頂層 `skills/` → inventory 第 3 項紅;只重現於 `plugins/*/skills/` → 第 7 項紅;
> 但**若有人把它加回 `PLUGINS` 成分並同時重建 `skills/zh-style/`,全部閘同時轉綠**
> ——分岔以完全一致的姿態回歸,現有閘一根手指都不會動。

落地為 `engine_not_a_skill()`,**五端全部由同一個綠端單點突變產生,逐一實測可達**:

| 端 | 判定 |
|---|---|
| 綠端 | 引擎在 `engines/`、出貨齊、不在任何 `skills/` | 綠 |
| 腿一 | 加回 `PLUGINS` 成分 | 紅 |
| 腿二 | 出現在頂層 `skills/` | 紅 |
| 腿三 | 出現在 `plugins/<p>/skills/` | 紅 |
| 腿四 | 引擎樹裡出現 `SKILL.md` | 紅 |
| **出貨腿** | 宣告了卻沒出貨 | 紅 |

**第五腿是刻意的**:三腿只擋「引擎變回前門」,擋不住「引擎一起消失」——
那是被使用者排除的候選 A,而**假綠不會因為它是被排除的方案就不出現**。

腿四是把散文端**唯一判得動的部分**收進資料端:措辭層(README 是否仍宣稱「不是前門」)
依 `KN-001` 第二條路**明講靠人**,不造 NLP 誤殺面。

## `.4` — 不用下一個會過期的手抄數字換掉這一個

`version_impact_check.py` 的「21」四處、「`fiction` 被 7 個」一處、`catalog_check.py` 一處。
實測 marketplace 是 **10** 個 plugin、`fiction` 被 **1** 個打包——兩個數字都過期。

**fable 的判定:不要把 21 改成 10。** 已改寫成指稱關係
(「打包它的每一個宿主」),不含現況計數。全 repo 剩餘命中只有一處,
是本次改寫**自己的歷史陳述**(「原文寫死『21 個』與『fiction 被 7 個』」)——
那是說明改了什麼,不是現況計數。

可判的最小替代「治理腳本敘述不放現況計數」是**寫作紀律,不是斷言**,依 `KN-001` 明講靠人。
