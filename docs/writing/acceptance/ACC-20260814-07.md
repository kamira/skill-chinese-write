### 證據 B — 名冊解析

`load_registries(repo, ref)` 從 blob 讀,`--since` 的兩端各呼叫一次。

### 證據 C — 理由聚合的形狀

`aggregation_test()` 不只驗「有紅」,驗**形狀**:同時改 skill 內容與手寫檔,
alpha 必須只出**一則**版號訊息,且該訊息同時含兩個理由。
抑制式實作在這裡會露餡——它只會列出先觸發的那一個。

## 審議席在我動手之前就找出的致命傷

**草案的 R4 在自己的定義裡自我取消。**

我原本寫:「plugin 的整棵出貨樹一個 byte 都沒變,但 `plugin.json` 的 version 動了 → 禁止」。

審議席(fable):**`plugin.json` 自己就在出貨樹裡。**
version 行動了 = 樹變了一個 byte = 「樹沒變」**永假** = **R4 永遠不火**。

**一條紅端不可達的禁令,實效等於 fail-open。**

它把這歸為我那個病的第四種形態:

| 張 | 病的形態 |
|---|---|
| CHG-05 | 判準措辭偏鬆(豁免 vs 禁令) |
| CHG-06 | 判準措辭偏鬆(「不同」vs「遞增」、fail-open) |
| CHG-07 草案 | **規則在自己的定義裡失效** |

原話:「**更難從措辭上看出來**,所以 self-test 的 R4 紅端案是這張 CHG 裡
最不可妥協的一條。」那一案(案 27)現在存在且會紅。

### 另外兩處也是它糾正的

- **R3 不准列舉。** 草案寫「`plugin.json` 除 version 行外、README **等**」。
  列舉會讓下一個手寫檔靜默漏網,**正是這個 repo 的孤兒事故形狀**。
  改成補集:未知的檔落進「算」,不是落進「不算」。
- **理由要聚合,不准抑制。** 「抑制邏輯的 bug 是**靜默綠**,fail-open 的形狀;
  聚合邏輯的 bug 最多是理由列少一條,verdict 不變。」

## 我在實作中犯的錯

1. **名冊解析器只認雙引號,遇到單引號回空 dict 而不是報錯。**
   「解析不出來」與「真的沒有 plugin」長得一模一樣——**這道閘自己的靜默 fail-open**。
   已改成兩種引號都認,而且區塊有內容卻 parse 不出條目就直接報錯。
2. **合成夾具與正式格式不同。** 我用 `repr()` 產生單引號,而正式的
   `build_suite.py` 用雙引號。夾具不像真的,自檢就會驗到一種正式樹裡
   不存在的形狀——上面那個 bug 就是這樣被掩蓋的。已改成一致。
3. **又用腳本替換多行字串把檔案改壞**,第二次。已知教訓是改用 Edit 工具,
   而我又走了捷徑。
4. **我在 ACC 裡貼了一段腳本從來沒印過的輸出。**
   證據 A 初稿引「✅ self-test:**31** 案全過」,而腳本印的是「**30** 案」。
   成因:改完橫幅之後我只看了 `tail`,沒看第一行——**宣稱沒有對過量測**,
   在這個 repo 已經是第三次。複審(fable)判它 merge-blocking,並附了一句質疑:
   「若你的輸出真印 31,我們跑的不是同一份碼,請對質。」我跑了,是我錯。

   修法不是把 30 改成 31,是把橫幅改成**數出來的**:
   `f"{len(ran) + len(EXTRA)} 案全過"`。寫死的數字每加一案就要記得改,
   而漏改的後果不是少報一個數,是**那個數字被抄進 ACC 當引文**。

### 同車修掉的 P5

## 複審記錄在案的殘餘(方向是誤殺,不是放行)

- **P6 是死鎖形,不是單純誤殺。** 我初稿把它寫成誤殺,複審判為**不準確**。

  三讀 probe(T2/T3/T4)實證的三角:

  | 動作 | 結果 |
  |---|---|
  | 單獨重排 `plugin.json`、不 bump | **紅**(R3:手寫檔變了) |
  | 單獨重排 `plugin.json`、有 bump | **紅**(R4 誤指「驅動源全靜止」,而它沒靜止) |
  | 重排 + bump + **一個真實的手寫變更** | 綠 |

  也就是說,**單獨重排 `plugin.json` 的 commit 從此沒有綠路**——不 bump 紅、
  bump 也紅。唯一出路是同 commit 搭載一個真實變更。

  這個 repo 自己立過「**死鎖比誤殺更糟**」(CHG-20260814-06 案 19)。
  它不到 merge-blocking——操作罕見、可避免、兩路皆紅**不靜默**、出路存在
  ——但必須具名為死鎖並寫明出路,不能含混成誤殺。
- **P11**:`metadata:` 底下**巢狀**的 `version:`(如 `metadata.sub.version`)會被
  一併剝掉,判成戳記紅,訊息是「metadata.version 從 1.0.0 動到 1.0.0」
  ——案 19/31 那族死鎖再深一層。罕見形狀。
- **P7**:tuple **純換序**(出貨 byte 不變)也要求 bump。保守向誤傷。

P7 與 P11 記在此不修——**方向是誤殺不是放行**,而誤殺會被人看見並回報,
放行不會。P6 同樣不修,但它是死鎖不是誤殺,已如上具名。
