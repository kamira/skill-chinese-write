### 證據 B — 名冊解析

`load_registries(repo, ref)` 從 blob 讀,`--since` 的兩端各呼叫一次。
`_parse_registry` 在兩種情況直接 `SystemExit`,不 skip:
區塊找不到、以及**區塊有內容卻一個條目都 parse 不出來**。

### 證據 C — 理由聚合的形狀

`aggregation_test()` 不只驗「有紅」,驗**形狀**:同時改 skill 內容與手寫檔,
alpha 必須只出**一則**版號訊息,且該訊息同時含兩個理由。
抑制式實作在這裡會露餡——它只會列出先觸發的那一個。

## 審議席在我動手之前就找出的致命傷

**草案的 R4 在自己的定義裡自我取消。**

我原本寫:「plugin 的整棵出貨樹一個 byte 都沒變,但 `plugin.json` 的 version 動了 → 禁止」。

審議席(fable):**`plugin.json` 自己就在出貨樹裡。**
version 行動了 = 樹變了一個 byte = 「樹沒變」**永假** = **R4 永遠不火**。

**一條紅端不可達的禁令,實效等於 fail-open。**

它把這歸為我那個病的第四種形態:

| 張 | 病的形態 |
|---|---|
| CHG-05 | 判準措辭偏鬆(豁免 vs 禁令) |
| CHG-06 | 判準措辭偏鬆(「不同」vs「遞增」、fail-open) |
| CHG-07 草案 | **規則在自己的定義裡失效** |

原話:「**更難從措辭上看出來**,所以 self-test 的 R4 紅端案是這張 CHG 裡
最不可妥協的一條。」那一案(案 27)現在存在且會紅。

### 另外兩處也是它糾正的

- **R3 不准列舉。** 草案寫「`plugin.json` 除 version 行外、README **等**」。
  列舉會讓下一個手寫檔靜默漏網,**正是這個 repo 的孤兒事故形狀**。
  改成補集:未知的檔落進「算」,不是落進「不算」。
- **理由要聚合,不准抑制。** 「抑制邏輯的 bug 是**靜默綠**,fail-open 的形狀;
  聚合邏輯的 bug 最多是理由列少一條,verdict 不變。」

## 我在實作中犯的錯

1. **名冊解析器只認雙引號,遇到單引號回空 dict 而不是報錯。**
   「解析不出來」與「真的沒有 plugin」長得一模一樣——**這道閘自己的靜默 fail-open**。
   已改成兩種引號都認,而且區塊有內容卻 parse 不出條目就直接報錯。
2. **合成夾具與正式格式不同。** 我用 `repr()` 產生單引號,而正式的
   `build_suite.py` 用雙引號。夾具不像真的,自檢就會驗到一種正式樹裡
   不存在的形狀——上面那個 bug 就是這樣被掩蓋的。已改成一致。
3. **又用腳本替換多行字串把檔案改壞**,第二次。已知教訓是改用 Edit 工具,
   而我又走了捷徑。

## 刻意不做的
