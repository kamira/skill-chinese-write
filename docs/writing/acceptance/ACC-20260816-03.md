## 決策鏈與兩處我被糾正

```
我的提案      freeform 八支全併         → 兩席駁回
使用者裁示    作文 / 歷史 / 藝術         → 判準從實作狀態換成文體家族
兩席          歷史→文言、藝術不落地      → 使用者確認
使用者二裁    新詩偏向藝術或作文         → 兩席分歧
互審          codex 三點全部改判         → 兩席一致採作文
使用者確認    併入作文                   → 定案
```

**審議席糾正我兩處**:

1. 「新裁示推翻 `drama` 的獨立」——**不成立**,那是**條件式推翻**,
   條件(選藝術組)未成立。poetry 歸作文後 drama 仍是單成員
2. 「退役 6 變 8」——**是 6 變 7**。drama 不動,我把它一起算了

**決定分歧的論證**(fable,codex 接受):

> KN-003 第一層量的不是「找不找得到」,是**安裝意圖存不存在**。
> 「詩歌與劇本」——想寫詩的人不想要劇本,想寫劇本的人不想要詩。
> 而且列舉式命名是**萬能溶劑**:照這規則,`freeform` 只要改名叫
> 「散文與記敘與…與詩與劇本」就過關了。**一把什麼都能過的尺不是尺。**

我提的反例(`composition` 的 description 就是列舉)被回答為:
**名字負責被找到,列舉負責讓人核對**;把列舉放進 name 欄是**把成分表當品名**。

## 我在本張裡犯的錯

1. **`plugin.json` 漏建**——新 plugin 需要 `.claude-plugin/plugin.json`,
   `build_suite` 只同步 skill 副本。**加法這條路是這批工作第一次走**,
   由 `catalog_check` 擋下。
2. **差點把 `poetry` 的 keywords 抄進 `composition`**——我用 `poetry` 的 plugin.json
   當模板整份複製。**沒有任何斷言在看 keywords**,那會讓 marketplace 搜尋把
   「作文」配對到「詩」。**結構可以照抄,內容必須逐欄想過**,我第一次把這兩件事混成一件。
3. **三次探針設計錯,同一個根**:
   - backlog 來源探針拿描述性詞句 grep 程式碼 → 5 條假陽性
   - 紅端探針第一版改工作樹沒 commit → 4 發假陰性
   - 墓碑探針用單空格,而真檔是對齊排版 → **空操作**,假陰性
   三次都是**照我以為檔案長什麼樣造探針,不是照它實際長什麼樣**。
   第三次靠 `assert n == 1` 才抓到——沒有它,空操作的綠會被當成「規則沒洞」。
   這正是 `CHG-20260814-08` 記過的:「突變構造錯了會證明不了要證的東西,
   而它看起來很像成功了。」我記下它,然後在三個不同位置各犯一次。
4. **改了主體、漏了周邊**——poetry 併入後,CHG 的 Type 欄、驗收條件、紅線二、
   設計圖仍寫著舊數字,還有一整段與新段落重複。
   `CHG-20260816-02` 才把這個形狀記為可預測盲區,所以這次我沒有通讀、
   直接掃數字與重複段。
