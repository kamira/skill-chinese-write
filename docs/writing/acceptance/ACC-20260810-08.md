## 這一輪最值得記的一件事

**「加夾具」這個動作本身,把一條錯誤的規則逼了出來。**

樣稿放進 repo 之前,成語下限那條錯了沒有代價——沒有東西會跑到它。一旦它們變成 CI 夾具,那條錯誤的警告就會**在每一次 CI 印出來**,而且對半數流派說反話。

這是「夾具不只是驗證工具,它決定了哪些規則會真的被執行」的第二個例子。第一個是 CHG-20260810-09:錯的夾具遮住了 `[::]` 那個壞掉的規則。這次反過來——**對的夾具逼出了壞掉的規則**。

兩件事的方向相反,底層是同一句話:**規則的正確性,是由跑到它的輸入決定的**。沒有輸入跑到的規則,對錯不會有人知道。

## 誠實的邊界

1. **驗收者與實作者是同一個。**
2. **八份樣稿是重寫的。** 暫存區在使用者提問前被清空,內容從對話紀錄的最終版重建。七篇有逐字紀錄,詩歌那篇是原稿加一次記錄在案的結尾替換。已用 lint 實跑驗證,但**與使用者手上那份可能有字句差異**。
3. **沒有 lint 的四支仍然只有正字法在管。** `zh-style` 檢查標點與收尾,檢查不了散文寫得好不好——那一半仍然靠人。
4. **佔位字串的判定只看標頭。** 內文裡的 `<...>` 不管,因為那可能是正當的角括號用法。
5. **移除下限之後,「成語太少」不再有任何提醒。** 這是刻意的:原文沒有這條要求。若日後真的需要,得先在 `chinese.md` 或使用者的指令裡找到依據。
