## 驗收條件與證據

### 1 主修復:`clean_git_env()` 補集定義

十項列舉被兩席**各自獨立**打回,理由同型:名單窄於規則自己寫的範圍。
fable 舉出列舉必漏的具體例子——使用者跑 `git -c core.worktree=/別處 push`,
hook 子行程繼承 `GIT_CONFIG_PARAMETERS`,十項全清之後 sandbox 裡的每個 git 照樣被拉走。
codex 給的是問 git 自己(`git rev-parse --local-env-vars`,本機 git 2.55 回 15 項)。

採補集定義(fable),並把 `--local-env-vars`(codex)用成**斷言的基準**而非清單來源。
未知的新變數落進「清」,不是落進「留」。

### 3 `.3` 的兩個缺陷都是審議席抓的,而主 agent 的三道自驗全盲

**缺陷一:落地的是控制位元組 `0x01`,不是字面的反斜線加一。**
兩席**獨立各自**抓到(codex 逐位元組讀、fable 用磁碟 bytes 實跑)。
但後果的判斷不同,**以實跑為準**:

- codex 推測「`set -e` 下直接紅退」
- fable 實跑:**靜默無作用**——`GIT_DIR=/tmp/x` 進、`GIT_DIR=/tmp/x` 出,`EXIT=0`,十九步全綠

主 agent 在沙盒重現,證實 fable。**主 agent 先前採信推測並轉述給使用者,那是錯的,已具名更正。**
紅退還會被人看見;靜默綠不會。

三道自驗全盲,每一道盲的理由不同:`bash -n` 對字串裡的控制字元合法;
主 agent 的「實測」把迴圈**重打一遍**在另一個 shell 裡跑,驗的不是這個檔(KN-004 的形狀);
肉眼 review 看到的 `0x01` 什麼都不是。

**缺陷二:紅端自己會說謊。** 事後斷言仍在解析 `env` 的**值**——白名單變數的值若含真換行、
換行後那段又長得像賦值,`sed` 會從值裡撈出一個根本不存在的變數名:

    GIT_TRACE=<值為「1」換行再接「GIT_FAKE=b」>
    → ❌ 呼叫端清 GIT_* 失敗,還留著:GIT_FAKE    rc=1

白名單運作正常,紅卻在說謊。這與第二輪測過的「值含換行」是同型輸入,
只因當時毒的是 `GIT_DIR`、**它先被清掉了**才沒觸發——測到的是同一族的另一側。
換成 `compgen -e | grep '^GIT_'` 之後同一條件轉綠,且該變數的值逐位元組原樣保留。

fable 就此**具名更正自己第二輪的話**:「兩套機制不會同病相憐」那句只在極性上成立;
`env` 這條路自帶另一個病——把**名稱與值混在同一份文字流**。現行版本是把病根拔掉:
行動端讀 shell 自己的變數表(參數展開),斷言端讀匯出名稱集(`compgen -e`),
**值永遠不進文字流**;而「會洩漏給子行程」的正是匯出集,斷言的範圍與要守的風險面精確重合。

### 4 `.3` 的覆核(五條件 + 紅端,全部用檔案本身的 bytes)

覆核方式本身也改過:上一版把迴圈重打一遍再跑,對 `0x01` 全盲。
現在一律 `sed -n '/呼叫端清 git 環境/,/^unset _left _v$/p' .github/ci_local.sh` 抽出來再跑。

| 條件 | 結果 |
|---|---|
| 毒化 `GIT_DIR` / `GIT_INDEX_FILE`,帶 `GIT_TRACE` / `GIT_TRACE_PACKET` | 前兩者 unset、後兩者留,rc=0 |
| **待清**變數的值含換行 | rc=0 |
| **白名單**變數的值含換行(codex 的假紅案) | 沒紅,rc=0 |
| 完全沒有 `GIT_*`,`set -euo pipefail` 下 `${!GIT_@}` | rc=0 |
| **CRLF 原樣 bytes**(本機 hook 實際吃的工作樹版本,fable 加驗) | 正確 |
| 紅端:行動端整段換成 `:`(語法合法) | `❌ … 還留著:GIT_DIR`,rc=1 |

全檔控制字元掃描:無。行動端與斷言端兩行**連一個反斜線都沒有**——
跳脫收斂那類事故連載體都不存在了。

### 5 CHG 文件被主 agent 自己剖開三次

`- Diagrams: 見 ` 加反引號加 `## Design diagrams` 加反引號**才是第一個匹配**——

Diagrams 欄改為不含可被當錨點的完整標題。

### 6 跳脫收斂連咬三次,而且每次都在同一段

寫進 `ci_local.sh` 註解的跳脫序列在轉手之間被收斂掉一層,三次:
第一次造出 `0x01`;第二次修它的註解又造出 `0x01`;第三次把註解切成兩行、
第二行帶一個落單的單引號,`bash -n` 當場紅。
處置:凡要寫進檔案的跳脫序列,**一律用碼值組字,不寫跳脫**。
