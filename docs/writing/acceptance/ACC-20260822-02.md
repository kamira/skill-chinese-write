## 驗收條件與證據

### 1 A/B 決定性測試

| `docs/changes`(工具寫死的位置) | 1 條 → 紅:「驗收懸空」 |

兩側都要成立,否則本閘的整個前提沒有證據。

### 2 歸因:八格空轉分兩種成因,兩席各自獨立修正了主 agent

主 agent 原本把「回傳 0 條」一律歸成路徑病。**兩席獨立指出這是錯的**,拆法一致:

- **四格是路徑病,修好路徑就活**:`check_chg_acc` / `check_fields` /
  `check_recurrence_field` / `check_knowledge_bootstrap`。
  fable 實測:把 `docs/writing` 鏡射進 `docs/`,前三格立刻噴出 **11 + 34 + 4** 條。
- **四格修好路徑也不會活**:標的物在本 repo 不存在。其中 `check_coverage_registry`
  用的是 `repo.glob("docs/*/acceptance/…")`——**同一個檔案裡已經有正確的 glob 寫法**。

**任何驗收判準都不能宣稱「修好路徑會救回八格」,只會救回四格。**

codex 另抓到**第三個假宣稱**:`check_structural_sync` 只在帶 `--staged` 時執行,
而 `[15/19]` 呼叫時沒帶。三個宣稱裡只有 secrets 是真的。

`check_entry_point` 用 `docs/changes` 存廢判「受不受治理」,把本 repo 判成**未受治理**——
「治理專案必有 AGENTS.md」對本 repo 從未生效過。AGENTS.md 剛好存在,**那是巧合,不是保護**。

### 4 止血條款:補齊既有宣稱的覆蓋,不是新增宣稱
