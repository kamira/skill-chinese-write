## 這一輪最值得記的一件事

寫完之後清點斷言,發現 **`章節字數` 那條沒有任何夾具會觸發**——兩份樣稿都沒有章節標題。

規則在 JSON 裡有欄位、腳本裡有斷言、文件裡有說明,三樣俱全,唯獨沒有東西證明它會響。這是 KN-001 往下一層的同一個毛病:上一層是「規則沒有斷言」,這一層是「斷言沒有夾具」。兩者的後果一樣——文件看起來完整,實際上沒有人在把關。

補法很便宜(在 `sample-bad.md` 加一個章節標題),但**要先去清點才會發現**。所以這件事的價值不在那三行 diff,在於「寫完之後逐條清點斷言有沒有被踩到」應該變成預設動作。

## 代使用者做的決定(請覆核)

1. **成語比例改為自訂密度指標。** `chinese.md` 給的是百分比(如武俠 25%-35%),但沒有定義分母。不冒充實作,改用「成語次數/千字」,區間依原文各流派的相對高低自訂(武俠 8-14、科幻 1-3⋯⋯)。三處文件都標明是自訂。
2. **純對話輪數門檻放寬一級。** 原文寫「超過 3 輪必須插入人名」,但它自己的示範正好是 4 輪。門檻設在 5 輪才報——一個會把規格自己的範例判違規的門檻,只會教人忽略警告(KN-002)。
3. **`writing` 的 plugin 版本 bump 到 1.4.0**、`homepage` 由 `kamira/ai-skills` 改為 `kamira/skill-chinese-write`(拆 repo 後那個網址一直是錯的)。

## 誠實的邊界

1. **驗收者與實作者是同一個。** 中風險原則上要 verifier ≠ implementer,本輪沒有第二個驗收者,如實記下,不假裝滿足。
2. **成語表只有約 140 條。** 涵蓋常見的武打、懸疑、情感、環境類,但遠非完整;成語密度因此是**低估**。文件未宣稱它完整。
3. **沒有真的寫一篇長篇小說來驗。** 夾具是 536 字與 440 字的片段。章節字數區間(5000-8000)因此只驗到「警告會響」,沒有驗到「一個真正 6000 字的章節會安靜通過」。
4. **對話換行的判定是啟發式的。** 用「同段引號數量」逼近「有沒有換人說話」,判不出同一人在同段第三次開口(那是合法的,但會被判違規)。這是刻意選的偏誤方向:寧可誤報一個罕見的合法寫法,也不要漏掉常見的錯誤排版。
