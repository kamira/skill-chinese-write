## 審議席抓到而我沒抓到的

### 一、我把禁令寫成了豁免(fable)

草案的判準表中間那一列寫「skill 只有戳記變 → **沒有人**需要 bump」。
fable 判它是**定稿前必改的一處**:

> 放行式寫法留下的洞不只是漂移:它讓「先無內容動戳記、下一張 CHG 再動內容」
> 把一次內容變更拆成兩個各自全綠的 diff 成為可能。

判準必須雙向:內容變 → 必 bump;內容沒變 → 戳記**必凍結**。
少了後半條,前半條可以被繞過。

### 二、「必 bump」被我寫成了「不同」(fable)

內容變更 + 版號 `1.1.0 → 1.0.1`,diff 非空,照字面規則綠。
`catalog_check --since` 現行就只比「不同」——**我差點原樣抄過來**。

### 三、fail-open 從方便變成承重牆的裂縫(fable)

見證據 C。

### 四、「嚴格更強」這個框架本身是錯的(codex)

我原本把退役寫成「替代品必須嚴格更強,否則就是拆閘」。codex 糾正:

> 不是嚴格更強,而是刻意改變不變量。

`writing` 那次的分岔形狀,新規則組**故意不再擋**。所以驗收要驗兩件事
(6a 必紅、6b 必綠),而不是「證明仍抓得到」。6b 寫成綠端案例,
是為了讓後來的人看得出這是決定不是疏忽——沒有它,
下一個看到「版號不一致卻沒紅」的人會把它當 bug 修回去。

### 五、戳記不收回,理由比我想的深(fable)

我以為收回 1.1.0 可以治好 `ACC-20260814-05` 記的瑕疵。fable 指出收回只是**把病搬家**:

- catalog 2.5.0 已經出貨,已裝使用者手上的 byte 收不回來,
  「`fiction-flash` 1.0.0 對應兩種 byte 狀態」在歷史裡是**不可逆事實**
- 收回的當下 `fiction` plugin 自己停在 1.1.0(command bump 是對的,不能動),
  於是 **`fiction@1.1.0` 立刻變成一號兩狀態**——治好六個、新開一個
- 還附送一個未來地雷:fiction skill 下次真的內容變時,自然 bump 目標是 1.1.0,
  而那個號碼已經在歷史上綁過另一種 byte,**號碼重用就是同一個病回到 skill 層**

codex 同向:「已進 main 與 catalog 的版號不可倒退。」

## 有意識接受的殘餘風險

**base 上已經存在的分岔,任何 diff 式的閘都永遠看不見。**

舊斷言是**狀態式**的(每趟靜態檢查重查現況),新規則組是 **diff 式**的
(只看 `base..HEAD`)。這個轉換丟掉的不只 writing 那一個形狀:
凡是在新閘上線之前就已存在於 base 的不一致,新規則組一律看不到。

審議席要求這句話白紙黑字寫下,不能默默吞掉。能被接受的唯一理由是:
戳記凍結保證這類不一致從此無法被**引入**。已經在裡面的要靠別的方式清,
那不是本張的範圍。

## 這一半比我原本寫的還大(複審補充)

`PLUGINS` 的**成分變更對本閘完全隱形**:從 tuple 移除一支 skill
(宿主出貨樹少一整支)→ 綠;把既有 skill 掛進新宿主 → 綠。

所以下一張的範圍是三項,不是一項:

1. plugin 自身檔案變 → 該 plugin bump
2. **`PLUGINS` / `COMMANDS` 成分變更 → 該 plugin bump**(本張隱形)
3. plugin 層的凍結方向(無內容的 plugin bump 禁止)——案 11 刻意放行「分岔」,
   但它同時放行了「plugin 無內容 bump」,而 `CHG-20260814-03` 打的正是那個病
