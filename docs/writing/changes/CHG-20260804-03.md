## 動機

CHG-20260804-02 的 ACC 自己寫了一句「**能跑不等於跑過**——目前只驗到 `plan-check` 與 `--help`」。
這張就是去收那一句。

## 跑過之後才發現的兩件事

**一、我自己寫的 CHG 標題層級是錯的。** `verify` 停在
「缺實際操作驗收」,但 CHG-20260804-01 / 02 明明有驗收節——寫成了 `## Acceptance operation`,
而 `lib/plan.py` 的 `AOP_RE` 認的是 `^###`。

`plan-check` 全過、`doc_integrity_check` 全過、CI 全綠,**沒有任何東西發現它**。
只有真的走到 `verify` 那一步才現形。這正是「能跑不等於跑過」的具體代價。

**二、沒有 `--verify-cmd` 時,verify 只會停下來等人。** 在 CI 上「等人」與「沒驗」
看起來一模一樣。所以補了 `.github/verify.sh`——把 ACC 的 operate 節寫成可重跑的指令,
其中第 4 步是**刻意讓漂移檢查轉紅**再還原:一道只證明得了綠燈的閘,證明不了自己有用。

## 這一輪沒有做到的(明說)

`build` 與 `review` 需要 `--agent-cmd` / `--review-cmd`(要有模型)。這兩個角色在本輪
**如預期地停下**(exit 3),沒有假跑。所以本 repo 目前證明到的是:

| 角色 | 狀態 |
|------|------|
| `plan-check` / `status` / `verify` / `accept` | **實跑過,綠燈可達** |
| `review` / `build` | 只證明到**停點正確**(exit 3,理由正確);未接模型 |

## 使用者故事

1. 作為維護者,我要 verify 有可重跑的指令,以便 CI 上「等人」不會與「沒驗」長得一樣。
2. 作為維護者,我要驗收腳本自己證明紅燈可達,以便它不是只會蓋章。
3. 作為維護者,我要 CHG 的驗收節被 runner 讀得到,以便那一節不是寫給人看的裝飾。

## 修改指引

### Goal

實際走完 runner 的角色鏈,並把驗收節變成可重跑的指令。

### Global Constraints(每個 task 都要遵守)

- 不接模型的角色**如實記為未證明**,不得以 dry-run 冒充跑過
- 驗收腳本必須同時證明綠燈與紅燈可達
- 隨身副本不得就地改(驗收腳本的探針必須還原)

### Tasks(checkbox=續作點)

- [x] T1. 修正 CHG-20260804-01 / 02 的驗收節標題層級(`##` → `###`)
  - interfaces: consumes lib/plan.py 的 AOP_RE / produces 讀得到的驗收節
  - test: `verify` 不再回報「缺實際操作驗收」
- [x] T2. 新增 `.github/verify.sh`:把 operate 節寫成可重跑指令
  - interfaces: consumes ACC 的 operate 節 / produces 可執行驗收
  - test: `verify --verify-cmd 'bash .github/verify.sh'` exit 0
- [x] T3. 走完角色鏈並如實記錄哪些沒證明到
  - interfaces: consumes runner / produces 證據表
  - test: verify exit 0;`accept --verified --dry-run` exit 0;review/build 如預期 exit 3

### Interaction spec

- kind: cli
- cmd: bash .github/verify.sh > artifacts/verify-session.log 2>&1
- artifacts: artifacts/verify-session.log

### Acceptance operation(實際操作驗收)

- **operate**:依序跑 `status`、`plan-check`(全部 CHG)、`verify --verify-cmd`、`accept --verified --dry-run`,以及不帶指令的 `review` / `build`。
- **observe**:各自的退出碼與訊息。
- **pass**:前四者 exit 0;後兩者 exit 3 且理由是「缺 review-cmd / agent-cmd」而非崩潰。

## Risk & rollback

- 風險:驗收腳本的漂移探針若沒還原會留下髒檔 → 緩解:`trap ... EXIT` 加結尾再還原一次,且最後重跑一次漂移檢查確認回到綠
- 回滾:刪除 `.github/verify.sh`;標題層級還原
