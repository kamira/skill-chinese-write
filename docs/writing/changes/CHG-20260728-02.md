## 決策

| # | 決策 | 理由 |
|---|------|------|
| D1 | 刻意句採**合併配額**,不逐類設限 | 使用者要管的是「不是常態」,也就是總量。分開設限會讓人把每一類都用滿,總量反而失控 |
| D2 | 明喻用 regex 偵測,隱喻不收 | GPTZero 的逐句理由把明喻(像)判 AI、隱喻(是)判人。**本 skill 不採信這個分界**——那是表面標記。但明喻確實是最容易寫成套路的一類,值得計數;隱喻與一般敘述無法機器區分,不收。**實作時兩度修正**:初版 `(?<![好想影圖印])像(?!樣)` 把「不像」「很像」「讀起來像機器」這類平常比較一併算入(誤報 4 處),收緊為排除否定與程度副詞、且要求「像」之後到標點前至少 3 字;另補 `antithesis_pattern` 抓工整反差(同一動詞重複、第二次帶否定),因為「擋得住掩體,擋不住⋯」前後差 1 字不算對稱,原設計漏抓 |
| D3 | 另計「段末刻意句」 | 被判最像 AI 的三句全在段落收尾。段末是斷語最容易堆積的位置,單獨設一個較嚴的上限 |
| D4 | **不砍**「至少一句 8 字以內」的短句要求 | 短句是節奏工具,跟斷語不是同一回事。真正的問題是短句加上總結姿態,那由段末上限管 |
| D5 | 偵測器的衝突寫成**已知代價**,不改既有規則去迎合 | GPTZero 的三個 AI 標籤(Lacks Creativity / Mechanical Writing / Lacks Creative Grammar)獎勵修辭與文學性,懲罰清楚、精確、標準語法——與本 skill 的核心主張正面相反。照它改等於把文章往華麗推。且其「Why is it AI」說明疑為事後生成的解釋層,未必是分類器實際特徵 |
| D6 | 風險分級「低」 | 純加法:新增一節規則與三項計數,全走警告不擋。既有硬性違規、退出碼契約與其他 skill 零變動;`sample-good.md` 須續過(列為驗收條件) |
