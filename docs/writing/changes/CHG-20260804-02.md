## 動機

拆分當下這個 repo 只帶了四支**檢查器**:doc-integrity、static、bilingual、knowledge-index。
那是「被檢查」,不是「被治理」——`plan-check` / `build` / `review` / `verify` / `accept`
與停點矩陣都不在,於是這裡的 CHG 格式沒有任何東西在把關,寫成什麼樣都不會紅。

## 為什麼帶整份 scripts/ 而不是算相依閉包

runner 會以**字串**指名同層腳本(`static_check.py`、`mutation_harness.py`、
`autopilot_sentinels.py`)。那種相依 import 分析看不到,算漏一支的後果是
**跑到那條路徑才炸**——而那通常正好是有人真的要用停點的時候。

另一個不可壓平的細節:`lib/` 以 `parent.parent.parent / "assets"` 定位資產,
所以目錄結構必須原樣保留為 `tools/autopilot/scripts/lib/` + `tools/autopilot/assets/`。

## 新閘對存量生效

接上 `plan-check` 之後,**既有的** CHG-20260804-01 立刻紅了:缺 `### Global Constraints`、
三個 task 都缺 `interfaces:` 與 `test:`。

正確處置是把存量**補齊**,不是把存量改成閘看不見的格式(把 `- [x] T1` 拆掉就會被當成
非 plan 格式而略過——那是最省事也最沒有意義的解法)。補上去的內容都是
ACC-20260804-01 已經記錄過的驗證方式,不是事後編的。

## 靜態檢查的範圍要明示

帶進來之後靜態檢查立刻紅四項 `shell=True`(`exec_util`、`ci_gate`、
`autopilot_sentinels`、`mutation_harness`)。上游**已經**對這四處具名豁免,
但豁免記的是上游路徑 `skills/ai-sdlc-autopilot/scripts/...`,對不上這裡的 `tools/autopilot/...`。

三條路:

| 做法 | 為什麼不選 / 選 |
|------|-----------------|
| 改帶進來的 allowlist | ✗ 那是就地改副本,漂移檢查會紅——而且該紅 |
| 在本 repo 另開一份 allowlist 重寫理由 | ✗ 同一件事兩個地方各有一份理由,遲早分岔 |
| **把靜態檢查範圍明示收在自己的程式碼** | ✓ 副本是逐位元組相同的東西,完整性由漂移檢查負責;重新稽核一份雜湊相符的副本不會增加資訊 |

代價寫明:repo **根目錄**新增的 `.py` 不在 `--paths skills plugins` 範圍內。
目前根目錄沒有 `.py`,若之後有,要一併加進範圍。
