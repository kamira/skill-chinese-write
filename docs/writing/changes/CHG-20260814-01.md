## 動機

`writing` skill 的精修循環跑了四輪(每輪另開 session 產文,寫手看不到討論、不准讀夾具)。
第三輪的做法是**改示範句**:把被跨題目抄走的示範句換掉、補上形狀不同的第二例、
並在檔案開頭寫一條規則「示範句是教動作不是給句型,形狀不可複用進成品」。

**第四輪證明這條路不收斂。** 三個實證:

1. 我把被抄兩次的「我手上沒有數字」改寫成講**證據等級**,R4 立刻寫出
   「證據等級就到這裡,不要當研究看」——換掉一個示範句,長出另一個指紋。
2. 教學 meta 詞「判準」持續漏進正文(R1「所以我要的判準是這個」、
   R4「我用的判準只有一條」)。原本登記的窄 regex 只認 R1 那個字串,
   **差點報出假的全清**。
3. 最難看的一條:本輪**剛加進**的 ✓ 收尾形狀「收在自己的失敗上」,
   R4 的後記**當輪即被採用**。新示範句上架,同一輪就被抄。

審議席的判詞:**句子不是錯的,「用指示防抄」是錯的。**
模型不服從「不可複用」的文字禁令,它複用**檔案裡最具體的東西**;
多放兩個形狀只是把抄襲分散到兩個形狀上。

## 施工:三條閘,依序

### G-1 教學 meta 詞不得出現在成品內文

規則文件用來**指稱動作**的詞(判準、讓步、證據等級、命題⋯),出現在成品正文即違規。
詞表放 `style_rules.json`,並立維護規則:`commentary.md` 每新增一個可名狀的動作詞,
詞表同步加。

**風險已知**:部分詞在日常中文是正常用語(「他不肯讓步」「他的主張」)。
施工時要對四篇受測稿與全部既有夾具做誤報測試,誤殺就收窄——
本輪已經因為過度一般化被使用者打回兩次,不重蹈。

### G-2 成品 × 規則文件 + 歷史樣稿語料的 n-gram 重合閘

`fixture_coupling_check.py` 的機制本輪剛修好(基準線棘輪、端到端 self-test、
法定用語直接刪除)。加一個**成品掃描模式**:拿一篇成品去比對
「規則檔 + references + 已收成夾具的歷史樣稿」,重合達門檻即紅。

意義:把「登記指紋」從**審議席人工追認**改成**機器自動**。
未來任何新指紋第一次重複就被抓,不用等下一輪審議發現。

### G-3 示範句全數登進 G-2 的比對語料,並在檔案裡明講

`commentary.md` 的 ✓ 示範句照留——**教動作需要具體**——但抄它從「被禁止」
變成「必被抓」。檔案裡明寫:以下例句已列入比對語料,抄了必紅。

這條順帶消滅「換一句長一句」:新示範句寫進去的同時就進語料,**不存在乾淨窗口**。

## 明講射程外的(KN-001 第二條路)

**章法層同構**(小場景→讓步→判準→拉遠)機器判不了。ACC-20260813-01 未達標第 2 條
已如實記錄,維持已知限制,不假裝閘蓋到。

審議席對 R4 的系列判詞:R1/R2/R4 三篇議題型的骨架已完全同模——
現象節恰三項條列 → 中段讓步 → 結語給一條判準 → 後記自陳位置。
**單篇都乾淨,並排一看是同一台機器。** 這一層本張不處理。

## Design diagrams

### 受影響區域

```
   ┌──────────────────────────┐        ┌──────────────────────────┐
   │ references/commentary.md │        │  歷史樣稿(已收成夾具)    │
   │  ✓ 示範句 ── G-3 登記 ──┐│        │  skills/*/assets/sample-*│
   └──────────┬───────────────┘│       └───────────┬──────────────┘
              │ 教學 meta 詞    │                   │
              ▼ G-1 詞表同步    └────────┬──────────┘
   ┌──────────────────────┐              ▼  比對語料
   │  style_rules.json    │   ┌─────────────────────────────┐
   │   meta_terms(硬禁)  │   │ fixture_coupling_check.py   │
   └──────────┬───────────┘   │   + 成品掃描模式  (G-2)     │
              ▼               └──────────────┬──────────────┘
   ┌──────────────────────┐                  │
   │  style_check.py      │                  │
   └──────────┬───────────┘                  │
              └───────────┬──────────────────┘
                          ▼
                ┌───────────────────┐
                │ 一篇新產出的成品  │  ← R5 用來驗證閘會動作
                └───────────────────┘
```

### 施工流程

```
  [1] G-1 詞表 + 硬禁斷言 ──→ 對 R1~R4 與全夾具做誤報測試
                               ├─ 誤殺 → 收窄詞表(不重蹈過度一般化)
                               └─ 乾淨 → 保留
  [2] G-2 成品掃描模式 ──→ 拿 R1~R4 當紅端測資(它們已知有指紋)
                            └─ 抓得到「證據等級」「判準」→ 閘可用
  [3] G-3 示範句登記 ──→ 新示範句寫入即進語料,無乾淨窗口
  [4] R5(最後一輪)──→ 驗證閘會動作
                        └─ 仍長新指紋 → 登進語料、記 KN、**照樣收尾**
                           (閘保證新指紋最多活一輪;循環上限一輪,寫死)
```

## 驗收條件

1. G-1:`style_check.py` 對 R1「所以我要的判準是這個」與 R4「我用的判準只有一條」
   皆命中;對四篇受測稿與全部既有夾具的誤報清單為空(或誤殺者已收窄並記錄)
2. G-2:成品掃描模式對 R4 抓得到「證據等級」(來自 commentary.md 示範句);
   對一篇自造的無關文章零命中
3. G-3:`commentary.md` 的 ✓ 示範句全數在比對語料內,且檔案裡明寫已列入
4. R5 產出後,上述三閘實跑一次並記錄結果
5. `bash .github/ci_local.sh` exit 0
