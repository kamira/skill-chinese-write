## 一、確定要修的 lint 缺陷(已逐條實證)

### D-1 成語密度的分母鉗位——這條規則從未被任何輸入跑到過

`skills/fiction/scripts/fiction_check.py:107` 寫的是 `per_k = max(total, 1000) / 1000`。
任何短於 1000 字的稿件,密度都被系統性低報。

實測武俠 good 夾具:**8 次 / 536 字 = 14.9/千字**,而 `wuxia` 上限是 **14**——應該亮警告。
lint 印出來的是「8.0/千字」,綠燈通過。

而**六份小說夾具全部短於 1000 字**,所以成語密度這條規則,在整個 CI 裡從來沒有真正被執行過;
唯一一份會踩線的輸入,正好被這個鉗位遮著。

改法:分母一律用真實 `total`;`total < min_sample_chars`(建議 300)時輸出
「樣本太短,密度未驗到」,**不得用鉗位分母冒充判過**。同時新增一份會踩紅的密度夾具,
否則警告分支依然是從未有輸入到達的死碼。

### D-2 「不是A,是B」的無「而」變體整組穿透

`style_rules.json` 的句型殼 regex 要求 `而是|而在於`。兩份 writing 夾具合計三處用逗號版
「不是⋯,是⋯」穿過去。zh-style 雖有這條,但只看最後一段且要求句尾。

兩位審議者**獨立指到同一批句子**(codex 點 `sample-issue.md` 的「不是準確率,是有沒有翻案的路」;
fable 另外點出 `sample-good.md` 的「不是不會寫,是不知道什麼時候該問」)。

改法:加進 `soft_limits` 而**不是硬性違規**——「我不是要大家搬回辦公室」這種否定意圖的用法
是正當的,硬禁會製造 KN-002 說的那種誤報。

### D-3 `zh_style_rules.json` 的 connectives 表被夾具污染

`flat_ending.connectives` 裡混著「上禮拜」與「那四十分鐘」。後者根本不是連接詞,是 narrative
夾具結尾的原文;前者對應 prose 夾具結尾。實測**兩個都是死條目**——那兩篇的結尾句都含逗號,
本來就不會觸發 `flat_ending`,白名單救的是不存在的誤報。

這是「調規則去遷就夾具」的痕跡,方向和 KN-001 要求的正好相反。刪除這兩個條目,
並在 self-test 補一組「短句開頭是通用連接詞 → 不警告」的案例取代。

### D-4 夾具與規則文件逐字耦合,沒有任何閘在管(本張最重要的一條)

四處實錘:

| 夾具 | 與什麼逐字相同 |
|---|---|
| `writing/sample-good.md` 多句 | `voice.md` / `commentary.md` 的示範例句原文 |
| `writing/sample-issue.md` 感受段 | `commentary.md` 的感受示範句原文 |
| `fiction-romance/sample-good.md` 結尾 | `zh_style_rules.json` 的 `flat_ending` 修正示範句 |
| `prose/sample-good.md` 結尾 | `zh_style_check.py:171` 的 self-test `GOOD` 字串 |

夾具引用規則自己的例句,等於**用考古題驗考生**——lint 對這些句子必然綠燈,因為規則就是照
它們校準的。這一條比上面任何單一 regex 都重要:它擋的是整類「夾具永遠測不到規則」的失效模式。

改法:新增獨立 CI 步驟,對 `skills/*/assets/sample-*.md` 與
`skills/*/references/*.md`、`skills/*/assets/*_rules.json`、`skills/*/scripts/*.py`
做 ≥10 字連續共用片段掃描,命中即紅。

### D-5 fiction 不看 markdown 強調記號

`fiction-scifi/sample-good.md` 的敘事文裡有 `**粗體**`,三支 lint 全部放行。
小說靠句子本身給重音;markdown 粗體是寫文件的殘留。加 warning 級斷言,
加完之後該夾具立刻提供一個紅端輸入。

### D-6 600 字下限寫在散文裡,沒有斷言

`commentary.md` 白紙黑字說「短於 600 字通常來不及論證,只夠喊口號」,而 `sample-good.md`
實測 **454 字**——good 夾具自己踩了自家下限。二選一:加 `length.min_chars`(警告級)並把
夾具補寫到 600 以上;或把 commentary.md 那句降級成非規則的經驗談。
維持現狀等於留著一條沒人執行的規則,正是本 repo 自己罵過的「比沒有更糟」。

### D-7 `doc_integrity_check.py` 的「草稿豁免」是一段不可達的程式碼

該腳本文件明寫「草稿與暫停(合法 WIP)不要求 ACC」。實際上:

```python
def classify_status(text: str) -> str:
    low = text.lower()
    ...
    is_draft = any(h in low for h in DRAFT_HINTS) and not any(
        h in low for h in ("已實作", "已驗收", "implemented", "accepted"))
```

`text` 是**整份文件**,狀態判定是對全文做子字串比對。兩個後果,第二個更嚴重。

**(a) 草稿分支不可達。** CHG 模板自己有一行 `- Implemented by: …`,`"implemented"`
永遠在文件裡,於是 `is_draft` 對任何使用標準模板的 CHG **恆為 False**。最小重現(已實跑):

| 輸入 | classify_status 回傳 |
|---|---|
| `狀態:草稿` | `draft` |
| `- Implemented by: Claude\n狀態:草稿` | `implemented_or_accepted` |

**(b) 「暫停」是一個誤觸即豁免的開關。** `PAUSED_HINTS` 在最前面檢查,而且同樣掃全文——
只要文件裡**任何地方**出現「暫停」或 `paused`,整份 CHG 就跳過 ACC 檢查。

這一條是本張施工時**踩在自己身上發現的**:上面 (a) 寫完之後,本張 CHG 反而通過了
`doc_integrity_check`。查下去,原因是我在 (a) 的敘述裡引用了腳本自己的註解
「草稿與暫停(合法 WIP)不要求 ACC」——**光是引用那五個字,就讓整份文件被判為 paused**。

實跑證據:`classify_status(本檔) == "paused"`;全檔唯一命中處是第 206 行的那句引文。

也就是說:任何 CHG 只要在正文提過「暫停」兩個字——討論排程、引用別的 CHG、
寫一句「本項暫停觀察」——就會**靜默**escape 掉「驗收不可懸空」這道閘。
規則寫了一個豁免,而觸發豁免的條件跟作者的意圖無關。

修法(送回上游):狀態判定只讀 `## Status` / `## 狀態` 節的內文,不要拿整份文件做子字串比對。

這支腳本屬於上游 `kamira/skill-ai-sdlc-autopilot`(本 repo 的 `tools/` 是隨身副本,
AGENTS.md 第 4 條明令不得就地改)。處置:**送回上游修**,不在本張動手。
修法是把狀態判定限縮到 `## Status` / `## 狀態` 節的內文,不要拿整份文件做子字串比對。

### D-8 `chg_field_check.py` 的佔位判定認括號不認語意

它的判準是 `^<[^>]*>$`——值整個被角括號包住才算佔位。所以草稿階段**沒有任何合法寫法**:
照模板寫 `<close-out 回填>` 會被擋,而只要拿掉角括號、寫任何一句話都會過,
即使那句話明顯不是 PR 連結。

本張暫時寫成「尚未開 PR(草稿階段;施工完成後回填實際 PR 連結)」以通過閘——
**但這正好示範了這道斷言的窄**:它擋得住模板殘留,擋不住「填了但沒填對」。
建議在 close-out 階段追加一條 URL 形狀斷言;草稿階段則應豁免,而不是逼人繞過。

兩條合起來是 KN-001 的第九、第十次觸發,且**都發生在治理規則自己身上**——
與 CHG-20260810-05 那次同型(那次是設計圖規則沒人查,這次是豁免分支沒人到得了)。
