# CHG-20260729-01 — writing v1.3.0:議題型文體、條列規範與豁免、禁短句收尾、lint 語言邊界

- 日期:2026-07-29(UTC+0)| 分支:claude/writing-skill-article-review-92efbc | 風險分級:低 | 實作者:Claude(Cowork session)
- 動機:使用者在 v1.2.0 之後連續給出五則寫作規格,並要求一次收進 skill。實際照規格寫一篇議題型示範稿時,lint 對條列連續誤報三次(粗體上限、平板連段、對稱句),另暴露引用誤判與標題被當句子兩個既有缺口;跑英文版時 lint 完全失效(找不到「我」、句長以字母計、明喻樣式抓不到 like)
- 使用者定調(五則,依提出順序):
  1. **「不管寫什麼,都不要在最後留一句簡短話詞作總結」**——絕對規則,故列硬性違規
  2. **議題型應表達感受,章節分三到四大類**:現象(簡短說明或只寫現象)/ 反觀或省思(**可選**)/ 結語 / 後記
  3. **「現象章節中間可以條列出項目,但需要簡單扼要說明」**
  4. **「反觀部分不一定要遵照反觀這詞」**,小標可用具體問句(例:「這篇真的是 AI 寫的嗎」)
  5. **「條列內禁止完整說明,只需要簡單扼要的重點」**+ 額外提供英文版範例

## 決策

| # | 決策 | 理由 |
|---|------|------|
| D1 | 最後一句字數下限列**硬性違規** | 使用者原話是「不管寫什麼,都不要」,語氣為絕對。與既有的結尾互動問句同屬「結尾」類硬禁,退出碼行為一致 |
| D2 | 條列整組**豁免於句子層級的所有判定** | 條列本來就該短而齊,拿散文的節奏標準去量它必然誤報。實測三次:三行條列 22/23/22 被判平板連段、改短後 11/9/10 再判一次、「逐句標色/黃是機器」被判對稱句。依 Global Constraint「誤報成本高於漏報」,整組排除 |
| D3 | 標題不計入句長統計,但另立標題檢查 | 「現象」被當成 2 字的句子,拉低最短句、扭曲 CV。標題該用自己的規則檢查(有沒有內容),不是混進散文統計 |
| D4 | 引號內的命中不計入刻意句 | 寫一篇討論明喻的文章,「它像戒菸貼片」與「有沒有『像』那個字」都被算成明喻。這是 use/mention 問題,與硬禁詞的 `--allow` 同源;但刻意句無 `--allow`,改用「引號內不計」這個更精準的通則 |
| D5 | 議題型的 `現象`/`結語`/`後記` 為**功能名**,允許直接當標題;可選的那節必須具體 | 使用者只鬆綁了「反觀」一詞。三個必要節保留功能名不影響可讀性,可選節的內容本來就因題而異,用結構標籤等於什麼都沒說 |
| D6 | 條列上限用**單項字數**,不用句數 | 「禁止完整說明,只要扼要重點」的可判定形式是每項的長度。設 `max_bullet_chars`,超過即警告 |
| D7 | 條列佔比門檻 0.15 → 0.25 | 議題型現象節合法使用條列後,示範稿實測 0.143 已逼近上限;再多一項就爆。放寬到 0.25,仍能擋住整篇條列化 |
| D8 | 英文只給**範例**,不做 lint 支援 | `style_rules.json` 每一條都綁中文:陸味對照、句型殼、以中文字元計的句長、抓「像」的明喻樣式。英文需另立規則集與斷詞方式,不是調門檻的事。本輪只落範例 + 在文件明講邊界 |
| D9 | 風險分級「低」 | 新增判定中僅一項為硬性(最後一句字數),其餘為警告或豁免(放寬)。既有硬禁詞、退出碼契約與其他 skill 零變動。**唯一破壞性影響**:`sample-good.md` 現行結尾「帳要算全。」會被新規則擋下,須改寫——列為驗收條件 |

- 英文不做 lint 支援,只給範例並在文件明講邊界——不得假裝支援
- 版本三處同步 1.3.0,catalog 必 bump;既有其他 skill 一字不動
