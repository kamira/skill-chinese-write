## 動機

`kamira/ai-skills` 是一個裝了三個 plugin 的 monorepo。使用者要把三者拆成三個私人 repo,
各自治理與編輯。本 repo 是其中之一。

## 這一輪的實質改動

skill 內容**一個字都沒動**,原封搬過來。改的只有載體,外加把治理能力帶進來:

| 項目 | 改法 |
|------|------|
| `.claude-plugin/marketplace.json` | 改為只列 `writing` 一個 plugin |
| `tools/` | 從 `kamira/skill-ai-sdlc-autopilot` 帶來四支治理工具的**副本** |
| `tools/PROVENANCE.json` + `tools_drift_check.py` | 記下帶過來當下的雜湊,並在 CI 檢查本地有沒有被改過 |
| `.github/workflows/governance.yml` | 新建:漂移、doc-integrity、靜態/安全、風格 lint 的 fixture 好過壞擋、py_compile、JSON、副本同步、catalog |
| `plugins/build_suite.py` | `PLUGINS` 只留自己那一組對映 |
| `AGENTS.md` / `README.md` | 重寫為單一 plugin 的進場說明 |

## 隨身工具的漂移是明說的盲點

`tools/` 是副本,不是本 repo 的原創。分開治理的代價就是副本會漂,而漂移有兩個方向:

- **本地被改過** —— `tools_drift_check.py` 查得出來(雜湊對不上)
- **上游前進了** —— 它**查不出來**,要主動同步

第二種是已知盲點,所以那支程式不印任何「工具是最新的」之類的話。
把查不出來的事說成查過了,比不查更糟。

## 使用者故事

1. 作為使用者,我要能對這個 repo 直接 `/plugin marketplace add`,以便不必安裝另外兩個不相干的 plugin。
2. 作為維護者,我要這個 repo 有自己的治理閘,以便拆出來之後不是「沒人管」。
3. 作為維護者,我要隨身工具被改過會紅,以便就地分叉不會無聲發生。
