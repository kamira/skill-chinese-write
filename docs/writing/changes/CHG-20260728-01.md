## 決策

| # | 決策 | 理由 |
|---|------|------|
| D1 | 句型殼走 regex 進 hard 表,但**逐條判斷硬/軟** | 參考來源把「先 A 再 B」「真正⋯的是」一律列高風險;繁中評論裡「我先講結論,再回頭談過程」是自然口語,一刀切會天天誤報。故:二元對比殼、「X 很簡單:」、助理路標詞 → hard;「先⋯再」「真正⋯的是」→ soft 密度 |
| D2 | `soft_limits` 擴充支援 `pattern`(原本只吃字面詞) | D1 要把句型殼放進軟限就得支援 regex。腳本改動極小,`hard_bans` 已有同樣機制可沿用 |
| D3 | 段落節奏用「**齊平判定**」而非只看變異係數 | 段落數通常少(5〜10),CV 在小樣本下不穩;改用「實質段落 ≥4 段且全距 ≤25 字」→ 判定段落一樣重,並輔以段落 CV 下限 0.25。門檻可在 JSON 調。**實作時修正**:`min_chars` 原訂 20(只看夠長的段落),實測發現這會把短段落排除在統計外——警告叫作者「插一個短段」,插了卻不算數。改為 4,只濾碎片,短段落必須計入 |
| D4 | 結尾互動問句列 **hard**,但以人稱為閘 | 「你覺得呢?」這類是明確的 AI 尾巴;但結尾一句真誠的反詰(「這筆帳,誰在付?」)是好收尾。故判定條件為:**最後一句是問句且含 你/大家/各位**,另加明確片語清單(不論位置)。純反詰不受影響 |
| D5 | 新增「改稿模式」為獨立 reference,不混進 `commentary.md` | 寫作與改稿的判準不同:寫作要「敢講死」,改稿要「不動作者的判斷、不編造事實」。混在一起會讓模型改稿時越權加料 |
| D6 | 五維自評 rubric 改編自 deslop,維度自訂 | deslop 的 5 維 ×10 分、35/50 門檻結構解決的正是本 skill v1.0.0 明說「lint 擋不住無聊」那一半。維度改成評論體適用(直說/節奏/信任讀者/具體/立場),不沿用原維度名 |
| D7 | unslop 的內容**不採用**,只參考公開描述的架構概念 | `theclaymethod/unslop` 無授權檔(`license.spdx_id` = NONE)。其 313 條詞表、77 條結構樣式一律不取;僅參考「分層掃描 + 保護性豁免」這類概念,規則自行撰寫 |
| D8 | 出處聲明落 `plugins/writing/THIRD-PARTY-NOTICES.md` | deslop 與 B1lli 皆 MIT,改編需保留著作權聲明。沿用 `plugins/ai-sdlc-suite/THIRD-PARTY-NOTICES.md` 的既有慣例 |
| D9 | 風險分級「低」 | 加法為主;唯一行為變更是 lint 新增判定,可能讓既有稿子新增違規——但 repo 內受檢的只有兩份夾具,且 `sample-good.md` 必須續過(列為驗收條件)。既有其他 skill 零變動 |
