## 動機

`ACC-20260814-03` 的 E-6 欄寫「diff 觸及範圍受限 ✅ **五檔**」。
實際上 PR #13 觸及 **7 檔**:

```
.github/verify.sh
docs/writing/acceptance/ACC-20260814-03.md
docs/writing/changes/CHG-20260814-03.md
docs/writing/knowledge/knowledge.md
plugins/build_suite.py
plugins/catalog_check.py
scripts/skill_inventory_check.py
```

**難堪的地方在於位置**:同一份 ACC 的「審議席抓到而我沒抓到的」第 4 條,
記的正是「我漏報觸及範圍——回報四檔,實為五檔」。
**我在承認漏報的那一頁上,又漏報了一次。**

成因:寫 E-6 時我用的是**寫 ACC 之前**的 `git status --short` 輸出(三個檔),
心裡加上先前記得的兩個,湊成「五檔」——沒有真的跑一次 `git diff --stat`。
數字是回憶出來的,不是量出來的。

## 一件必須一起記的事:我 merge 在裁決之前

使用者說「沒問題就 merge」,我判定沒問題就按了 —— **而審議席把 E-6 列為阻擋 merge 的硬傷**,
裁決在 merge 之後才到。

所以那個「沒問題」是**我判錯的**,不是授權有誤。
`main` 因此帶著一份有事實錯誤的 ACC 活了一段時間,由本張更正。

**留下的教訓不是「不要 merge」**,是:當一件事已經送審議席、而裁決還沒回來時,
「沒問題」這個判斷本身還沒有依據。停點的意義就在這裡。

## 為什麼不新建 KN

KN-004 是「**驗證的樹與寫入的樹不是同一棵**」;本次是「**驗收記錄的事實與被驗物不符**」。
兩者不同,但都屬**驗收完整性**這一族,而且成因同源:**用回憶代替量測**。

依 KN-003 立下的判準(第 2 次出現才建條目),本次先記為 KN-004 的第 2 次觸發證據
並擴寫其規則,不另立新條。**若第 3 次出現不同變體,再拆。**

KN-004 規則擴寫:留證不只要證明「被驗物在被驗的樹裡」,還要證明
「**寫進 ACC 的每一個數字都是當場量出來的,不是回憶的**」——
凡是數量、檔數、案數,證據欄必須附產生它的那道指令與原始輸出。
