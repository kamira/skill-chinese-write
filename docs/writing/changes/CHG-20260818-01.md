## 現象

`#26` 合併後在 main 上實跑:

```
$ python skills/ci-poetry/scripts/assets_verify.py
✗ baixiang:raw sha256 不符——資產與它宣稱的來源已經分家
✗ cilin:raw sha256 不符
  rc=1
```

而同一個 commit 的 CI 是**綠的**。

## 成因:git blob 是對的,工作樹是錯的

```
baixiang   資產宣稱 80170 bytes  sha ac69996f…
           git blob 80170 bytes  sha ac69996f…   CRLF 0      ← repo 內容正確
           工作樹   83739 bytes  sha d9f0989c…   CRLF 3569   ← 簽出時被注入
cilin      27665 → 28025(+360 個 CRLF)
```

`core.autocrlf=true` 是 **Windows 版 git 的預設**,簽出時把 LF 轉成 CRLF。
`.gitattributes` 已有 `*.sh text eol=lf`(而且註解寫明了行尾的坑),
**卻沒有涵蓋被 sha256 錨住的 vendored raw**。

於是:**任何 Windows checkout 上守恆閘都紅,而 CI runner 是 Linux,永遠綠。**

## 修法:兩層,缺一不可

### 一、`.gitattributes` 釘死

```
*.wikitext -text
```

### 二、補第 6 條:設定本身要被斷言

只加 `.gitattributes` 不夠。**如果有人把那一行刪掉,第 1 條的 sha256 紅端
只在 Windows 可達,Linux CI 照樣綠**——那條規則等於沒有被 CI 測過(KN-001)。

第 6 條把「設定有沒有寫」變成**平台無關**的斷言:vendored raw 若沒有被
`-text` / `binary` 覆蓋,Linux 上也會紅。

**保護 sha 的不是 sha 檢查本身,是這一條。**

### 「不在 git 工作樹」不是 fail-open

已安裝的 plugin 副本沒有 `.git`,第 6 條**不成立**而非通過——
它防的是 git 簽出時的轉換,**沒有 git 就沒有那個轉換**,條件本身不存在。
而這條路徑也被釘住:self-test 斷言本檔在 repo 內必須找得到 git 工作樹,
否則 `_repo_root()` 一壞,整條規則會在 repo 裡靜默消失而 self-test 全綠。

## 施工中我自己犯的兩個

1. **`REPO_ROOT = parents[3]` 寫死**——`skills/` 下算對,
   `plugins/classical/skills/` 下會指到 plugin 目錄,**而副本才是使用者裝到的那份**。
   改成往上找 `.git`。
2. **`... | head -3` 之後 `echo rc=$?`**——量到的是 `head` 的 exit code,
   印出 `rc=0` 而畫面上是紅的。**同一個錯本輪第二次**
   (前一次記在 `CHG-20260816-01`)。用 `PIPESTATUS` 才對。

## 驗收條件

1. 以 `core.autocrlf=true` 全新 clone,守恆閘 `rc=0`(修正前同條件 `rc=1`)
2. 第 6 條紅端在 **Linux 上可達**:刪規則 / 註解掉規則,兩種都要紅
3. 「不在 git 工作樹」的路徑被釘住,不是靜默通過
4. `_repo_root()` 對 `skills/` 與 `plugins/*/skills/` 兩處副本都解析正確
5. `ci_local.sh` 全綠;plugin 副本同步
6. 每個數字附產生它的指令(KN-004)
