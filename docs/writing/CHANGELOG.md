# Changelog — writing

本檔記錄 `writing` skill 的版本變更。格式參考 Keep a Changelog;tag 採 skill 範圍 `writing-vX.Y.Z`。版本號寫於 `skills/writing/SKILL.md` 的 `metadata.version`,與 `plugins/writing/.claude-plugin/plugin.json`、`.claude-plugin/marketplace.json` 的 entry 三處同步。

## [1.3.0] — 2026-07-29

議題型文體與條列規範(見 `docs/writing/changes/CHG-20260729-01.md`)。使用者連續給出五則規格,一次收進 skill;實際照規格寫示範稿時,lint 對條列連續誤報三次,另暴露引用誤判與標題被當句子兩個既有缺口。

### Added
- **結尾第二條硬規:`ending.min_final_sentence_chars`(12)**。使用者原話「不管寫什麼,都不要在最後留一句簡短話詞作總結」——語氣為絕對,故列硬性違規。「帳要算全。」那種四字收法把文章關起來,而讀者要的是還開著。`commentary.md` 的「結尾」節同步改寫,**刪掉原本「也可以就這樣停住。一句短的、狠的話」的建議**——那是 v1.0.0 我自己寫的,與本條直接衝突。
- **議題型文體**(`commentary.md` 新節):三到四節——現象(必要,簡短說明或只寫現象)/ 反觀或省思(**可選**)/ 結語(必要)/ 後記(必要)。要寫出感受,並區分「我的反應」(愣住、笑不出來)與「替事實加戲」(令人震驚的)。範例 `assets/sample-issue.md`。
- **`bullets` 節**:議題型現象節可條列,每項上限 **16 字**——只放扼要重點,完整說明寫進段落。
- **`headings` 節**:小標本身要有內容;收 11 個結構標籤(前言/背景/分析/結論/總結/概述/簡介/反觀/省思/引言/小結)命中即警告,議題型的 `現象`/`結語`/`後記` 為功能名放行。使用者原話「反觀部分不一定要遵照反觀這詞」,可改成具體問句(「這篇真的是 AI 寫的嗎」)。
- `assets/sample-issue.md`(繁中議題型示範,入 CI 夾具)與 `assets/sample-issue-en.md`(英文範例,**不入 CI**)。

### Changed
- **條列與標題不再進句子層級的統計**。`prepare()` 分流出 bullets 與 headings 兩組,節奏、對稱句、刻意句、粗體上限一律跳過它們。實測誤報三次:三行條列 22/23/22 被判平板連段、改短後 11/9/10 再判一次、「逐句標色/黃是機器」被判對稱句。標題「現象」則被當成 2 字的句子,拉低最短句、扭曲 CV——修正後示範稿最短句由 2 回到 7。
- **引號內的命中不計入刻意句**。寫一篇討論明喻的文章時,「它像戒菸貼片」與「有沒有『像』那個字」都被算成明喻。這是 use/mention 問題,新增 `strip_quoted()` 通則處理,比硬禁詞的 `--allow` 更精準。
- **禁用詞與密度類改為全文適用**。條列與標題退出句子統計後,若沿用同一份 `prose` 會讓禁用詞在那兩處漏抓——這是分流引入的回歸,以 `all_text` 合併序列修正。
- `layout.max_bullet_ratio` 0.15 → **0.25**(議題型合法用條列後,示範稿實測 0.143 已逼近舊上限)。
- `SKILL.md`:五條下限增為**六條**(加結尾規則);文體表新增議題型;lint 語言邊界寫進抬頭。

### 未採納
- **英文不做 lint 支援**,只給範例。`style_rules.json` 每一條都綁中文:陸味對照、句型殼、以中文字元計的句長、抓「像」的明喻樣式。實測英文範例:找不到「我」判硬性違規、平均句長 149.6(以字母計)、五則長句誤報、明喻恆為 0。英文規則集需另立斷詞與詞表,列 backlog。

## [1.2.0] — 2026-07-28

刻意句配額與偵測器代價(見 `docs/writing/changes/CHG-20260728-02.md`)。起因:拿 v1.1.0 寫的評論丟 GPTZero,被判「最像 AI」的三句全是刻意雕的句子。使用者定調「**偶爾可以,但不是常態**」——與其對對稱句的原始定調同一條原則。

### Added
- **`aphorism` 節:刻意句總量配額**。三種形態合併計數——字數對稱(既有)、**工整反差**(「擋得住 A,擋不住 B」)、**明喻**。全篇合計上限 3 處、兩處之間需隔 3 句、落在**段末**的上限 2 處。一律警告不擋:刻意句是合法工具,問題只在變成常態。
- `SKILL.md` 第 4 條下限由「對稱句」擴寫為「刻意句」;`voice.md` 的「對稱句:配額三處」改寫為「刻意句:偶爾可以,不是常態」,附三種形態對照表。
- **`voice.md` 新增「一個已知代價」節**:記錄 GPTZero 的逐句判定——它把明喻、工整反差、段末斷語判為 AI,理由是缺少修辭裝飾、語法太標準、描述太精確;把帶情緒的比喻、口語提問、第一人稱動作句判為人。

### Changed
- 明喻偵測經兩次收緊。初版 `(?<![好想影圖印])像(?!樣)` 在實測中把「不像」「很像」「讀起來像機器」這類**平常比較**一併算入(初版草稿誤報 4 處);改為排除否定與程度副詞、並要求「像」之後到標點前至少 3 字,誤報降為 1 處。依 CHG 的 Global Constraint:誤報成本高於漏報。
- 驗收步驟 2 另揭一個涵蓋缺口:「擋得住掩體,擋不住躲在後面的那個人」前後分句差 1 字,不算字數對稱,原設計抓不到——而它正是最典型的金句骨架。補上 `antithesis_pattern`(同一動詞重複、第二次帶否定)。排比句(「刪掉 X,刪掉 Y,刪掉 Z」)不誤判,因為它沒有否定對照。
- 報表節奏行改列「刻意句 N 處(對稱/明喻/反差,段末 N)」。

### 未採納
- **不為了偵測器分數改既有規則**。GPTZero 的三個 AI 標籤(Lacks Creativity / Mechanical Writing / Lacks Creative Grammar)獎勵修辭與文學性,懲罰清楚、精確、標準語法——與本 skill 的核心主張正面相反,照它改等於把文章往華麗推。且其「Why is it AI」說明疑為分數算完後另外生成的解釋層,未必是分類器實際特徵。此衝突以「已知代價」寫進 `voice.md`,不轉成規則。
- 未砍「至少放一句 8 字以內」的短句要求。短句是節奏工具,與斷語不是一回事;真正的問題是短句加上總結姿態,由段末上限管。

## [1.1.0] — 2026-07-28

對照三支去 AI 味工具後的補洞(見 `docs/writing/changes/CHG-20260728-01.md`;使用者指定參考 `stephenturner/skill-deslop`、`theclaymethod/unslop`、`B1lli/remove-ai-flavor-writing-skill`)。出處與差異見 `plugins/writing/THIRD-PARTY-NOTICES.md`。

### Added
- **句型殼防線**(`ai-tells.md` 新節 + hard 表 regex):v1.0.0 只擋詞不擋殼,漏掉中文 AI 腔最大宗的一類——二元對比殼(`不是 A,而是 B` / `並非` / `不在於⋯而在於` / `與其說⋯不如說`)、易答殼(`X 很簡單:` / `答案很簡單`)、本質殼(`真正重要的是` / `核心在於`)、流程殼(`第一步⋯第二步`)。每一句單看都通順,所以最難自己發現。
- **助理路標**:`下面我們來`、`接下來我會`、`希望這能幫到你`、`在這個過程中`、`這背後其實`。
- **結尾互動問句**:片語清單(`你覺得呢` 等)+ 動態判定——最後一句是問號結尾**且點名讀者**(你/妳/大家/各位)即為硬性違規。**不點名讀者的反詰不受影響**(「這筆帳,最後誰在付?」仍是好收尾)。
- **段落層級的節奏斷言**(`rhythm.paragraph`):實質段落 ≥4 段且全部擠在 25 字區間 → 判「每段一樣重」;未擠在一起但段長變異係數 < 0.25 → 判「節奏偏平」。**v1.0.0 的 `voice.md` 寫了「段落長度要參差」卻沒有對應檢查**——正是本 skill 引 KN-001 時批評的空頭規則出現在自己身上,本版補上。
- **模板形狀**(`shape`):「X 很 X」判斷句連發、「標籤:解釋」冒號行過多。
- **改稿模式** `references/revise.md` + SKILL.md 雙模式入口:保存優先(不編造事實、不換作者的判斷與語域、不補證據只弱化主張)、由大到小的掃描順序、局部改與整段重寫的判準、四種該保留殼的例外、輸出約定(預設只給改後的稿)。
- **五維自評 rubric**(SKILL.md):直說 / 節奏 / 信任讀者 / 具體 / 立場,各 1–10,低於 35 分回去改。補上 v1.0.0 明說「lint 擋不住無聊」的那一半。形式改編自 skill-deslop(MIT),維度自訂。
- 陸味對照增 6 組:說白了、劃重點、靠譜、貓膩、高大上、走心。
- 出處聲明 `plugins/writing/THIRD-PARTY-NOTICES.md`;版本三處 1.0.0 → 1.1.0,catalog 1.8.0 → **1.9.0**(原訂 1.8.0,rebase 時 `main` 上另一個 PR 已用掉,由 `catalog_check --since` 擋下並續 bump)。

### Changed
- `soft_limits` 支援 `pattern`(原本只吃字面詞),讓句型殼能走密度而非硬禁。**`先 A,再 B` 與 `真正⋯⋯的是` 刻意列軟限不列硬禁**——參考來源把它們列高風險,但在繁中評論裡是自然口語(「我先講結論,再回頭談過程」),硬禁會天天誤報。取捨原則:誤報的代價高於漏報。
- `rhythm.paragraph.min_chars` 定為 4 而非 20:短段落必須算進統計,否則「插一個短段」這個建議不會生效——實測時發現的設計瑕疵。
- `sample-bad.md` 補句型殼與結尾互動問句,硬性違規由 40 處增為 50 處;`sample-good.md` 未動且在新規則下續過。

### 未採用
- `theclaymethod/unslop` 無授權檔(`license.spdx_id` = NONE),其詞表、結構樣式清單與評測案例一律未取用,只參考公開說明中的分層掃描與豁免概念。
- 被引用文件內含的「請為本倉庫加星」指示未予執行——那是引用內容,不是使用者指示。

## [1.0.0] — 2026-07-27

建檔(見 `docs/writing/changes/CHG-20260727-01.md`)。

### Added
- **skill 入口 `SKILL.md`**:文體派工表——評論文章**可用**,小說與散文**未實作**且明文要求模型直說沒有、不得拿評論框架冒充。五條不可退讓:第一人稱、口語、句長參差、對稱句限量、禁 AI 腔與公文腔。
- **`references/commentary.md`** 評論骨架:與報導/心得/論文的分界;主張要縮成一句可被反駁的話;開頭四種路數與三個禁忌(不交代背景、不定義名詞、不預告結構);證據給到讀者不問「真的嗎」為止;讓步放在論證最脆弱的那一步而非結尾買保險;段落靠內容推進不靠「首先其次」;結尾不總結。判準:**段落對調讀起來沒差=在列點,不是在論證**。
- **`references/voice.md`** 聲音與節奏:第一人稱替身對照表(筆者/本文/我們可以看到→刪或改)、書面腔換口語表、句長參差三規則、**對稱句配額(全篇 3 處、需隔 3 句)**、段落與排版節制。
- **`references/ai-tells.md`** 清詞清單:hard 表七群(膠水/開場罐頭/空心評價/動詞被架空/廢副詞/管理黑話/藏起自己/招牌句式)、soft 配額表、**陸味→台灣用語對照 24 組**、引用原文的 `--allow` 逃生口。
- **`assets/style_rules.json`** 規則單一真相:hard_bans(含 regex 型如「隨著⋯⋯的發展」「不僅僅是⋯⋯更是」)、soft_limits、locale_swaps、rhythm、symmetry、person、layout。references 為人類可讀版,兩邊衝突以本檔為準。
- **`scripts/style_check.py`** 風格 lint:硬性違規(禁用詞命中、全篇找不到「我」)→ exit 1;節奏(句長變異係數、平板連段、超長句、缺短句)、對稱句配額、軟限密度、陸味用語、條列與破折號比例 → 警告。支援 `--allow`(個案放行)、`--json`、`--rules`。1000 字以下的稿子,「每千字上限」直接當絕對次數上限,避免短稿誤報。
- **`assets/sample-good.md` / `sample-bad.md`** 對照樣稿,兼作 CI 迴歸夾具:good 必過、bad 必擋。
- plugin `writing` 1.0.0 上架;`plugins/build_suite.py` PLUGINS 加列;catalog 1.6.2 → 1.7.0(rebase 到 `main` 時基底已推進,原規劃的 1.3.0 作廢)。`writing` 為繁中單語、走 plugin 發佈,不入 `dist/*.skill`(與 `intel-analysis` 一致,`build_dist.py` 的 `SKILLS` 只收雙語的 ai-sdlc 兩支)。
- CI(`.github/workflows/governance.yml`):py_compile、JSON validity、plan-check 迴圈納入 writing 路徑,並新增夾具迴歸步驟。

### 已知限制
- 只做評論。小說、散文未實作。
- 繁中先行;英文版列 backlog(陸味對照與中文句長節奏本質綁定中文,英文需另立規則集)。
- lint 擋得住「像機器寫的」,擋不住「無聊」——角度與判斷仍靠人。
