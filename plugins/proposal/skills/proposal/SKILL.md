# proposal — 企劃書

## 核心

規格化與標準化,開門見山,採用固定欄位、格式與專業術語。

**修辭比例**:趨近於零(0%-5%),嚴禁情緒化或模糊的修辭

## 怎麼寫

與公文、新聞稿同一族:倒金字塔結構、精準動詞、**數據圖表化**。

## 成語運用

低(5%-15%),用於標準化的行文致意或規模概括。

## ⚠ 本支沒有 lint,規則靠人判斷

**規格來源太薄**。`chinese.md` 把「公文、一般企劃、新聞稿」列為同一類,但只給了公文的三段法與新聞稿的倒金字塔——**企劃書自己的結構規範原文一句都沒有**。

不憑空發明:一份靠猜寫出來的規則,擋錯東西的機率比擋對高。

實務上可以先借用:`official` 的模糊指涉詞表與 `press` 的倒金字塔判定,兩者的方向都適用。跑法見那兩支。

上面每一條都是**寫作時的手感校準,不是斷言**。沒有任何程式在檢查它們,也不打算假裝有——寫成規則的樣子、放在規則文件裡、卻沒有人會執行,那種規則比沒有更糟,因為它讓文件看起來完整。

要判斷寫得好不好,只有一個辦法:自己讀一遍,問上面那幾條做到了沒有。

## 這個 repo 裡有 lint 的文體

評論(`writing`)、小說(`fiction` 與六支子層)、規格書與架構說明(`spec` / `architecture`)、公文與新聞稿(`official` / `press`)。各文體的狀態見 [`docs/genres.md`](../../docs/genres.md)。
