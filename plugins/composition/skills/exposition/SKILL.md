# exposition — 說明文

## 核心

依照時空或邏輯順序,客觀、平實地解說事物的特徵、構造、功能與原理。

**修辭比例**:**極低(5%-10%)**,追求準確,禁用誇張

## 怎麼寫

**詮釋**(下定義)、**譬喻**(僅限於淺顯易懂的打比方說明)。

手法上:下定義、**列數據**、作比較、分類別。

## 成語運用

低(5%-10%)。為了避免專業術語過於枯燥,用來進行「深入淺出」的常理對比或日常現象概括。

落腳:【引入日常類比的解釋性段落】。

## ⚠ 本支沒有 lint,規則靠人判斷

「有沒有列數據」勉強判得出來(找數字),但那是四個手法裡的一個,而且找到數字不代表用得對。

需要更硬的規範時,`spec` 與 `architecture` 兩支的模糊形容詞詞表可以借去用——那兩支的判定與說明文方向一致。

上面每一條都是**寫作時的手感校準,不是斷言**。沒有任何程式在檢查它們,也不打算假裝有——寫成規則的樣子、放在規則文件裡、卻沒有人會執行,那種規則比沒有更糟,因為它讓文件看起來完整。

要判斷寫得好不好,只有一個辦法:自己讀一遍,問上面那幾條做到了沒有。

## 這個 repo 裡有 lint 的文體

評論(`writing`)、小說(`fiction` 與六支子層)、規格書與架構說明(`spec` / `architecture`)、公文與新聞稿(`official` / `press`)。各文體的狀態見 [`docs/genres.md`](../../docs/genres.md)。
