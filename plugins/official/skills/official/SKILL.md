# official — 公文

> 判定邏輯在 **`bizdoc` 引擎**。本支管的是這個文體怎麼寫,以及該用哪個旗標。

## 核心

規格化與標準化,開門見山,採用固定欄位、格式與專業術語。目的是**讓對方知道要做什麼、到什麼時候為止**。

手法:主旨 / 說明 / 辦法三段法、精準的公文動詞、分項編號階層(一、(一)1.)。

**修辭比例**:趨近於零(0%-5%),**嚴禁情緒化或模糊的修辭**

## lint 會擋的(硬性違規,exit 1)

- **缺「主旨:」→ 擋**。說明與辦法視需要,主旨沒有例外
- 主旨超過 150 字 → 擋
- 情緒詞(令人震驚 / 深感痛心 / 可喜可賀)→ 擋
- 譬喻 → 擋(**結構排比不禁**)

## lint 會提醒的

主旨沒有公文動詞(請 / 查照 / 辦理 / 核示);模糊指涉(相關單位 / 妥為 / 儘速)

## 靠你自己判斷的(lint 判不了,明說)

- **致意用語得不得體**。「請查照」對上對下不同,這是關係判斷,不是字串比對。
- **格式階層用得對不對**。程式看得出有沒有編號,看不出層級對不對。

另外注意一件事:`writing` skill 把「制度」「窗口」「予以」整類公文腔列為**硬性違規**,而公文要的正是那套固定行文。**兩支絕不可混用。**

## 交稿前跑 lint

lint 不在本支——`bizdoc` 引擎的同一份規則檔服務多個前門,拆成多份會分岔。安裝本 plugin 時引擎會一起帶進來。

```
python3 skills/bizdoc/scripts/bizdoc_check.py 稿件.md --kind gov
```

引述他人原文而不得不出現禁用詞時,加 `--allow 詞1,詞2` 個案放行。

完整規範見 [`references/official.md`](../bizdoc/references/official.md)。
