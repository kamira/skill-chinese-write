# fiction-mystery — 懸疑 / 推理 / 驚悚小說

> 這是 **`fiction` 主層的子層**。主層管小說怎麼被讀進去(對話、分段、分章),本支管這個流派怎麼寫。

## 篇幅

不限篇幅

## 怎麼寫

以解謎、犯罪、恐懼心理為主軸。**嚴格遵循邏輯鏈條**,利用資訊不對稱製造緊張感,常用敘述性詭計與紅鯡魚偽線索。

多用**感官摹寫**(營造恐怖氛圍)、**抑揚**(刻意誤導)。

這個流派對修辭的限制不是美學,是功能:每一句華麗的句子都在干擾讀者的邏輯推導,而推導正是他們來看的東西。

## 兩個配比

| | 數值 | 誰在管 |
|---|---|---|
| **修辭比例** | 低至中(15%-20%) | **靠人判斷**——沒有程式量得出一段文字有幾成是譬喻 |
| **成語密度** | 2-5 次/千字(**文字要保持高透明度**) | lint 會數(`--genre mystery`),但區間是本 skill 自訂,不是原始規格的百分比 |

## 成語落在哪裡

① **直面恐懼**:主角突見屍體或陷入致命陷阱時的生理防線崩潰。
② **靈光一閃**:偵探在雜亂線索中突然看清真相的瞬間。

這兩處以外保持透明——讀者要能一眼看穿句子,看到句子底下的事實。

**落腳段落**:【驚悚氛圍渲染段】與【破案解謎的邏輯梳理段】

## 主層的硬規範一樣要遵守

換人說話就獨立成段(同段最多兩處引號)、段落字數上限(實體 150 字 / 網文 80 字且不超過 3 行)、擬聲詞不用「X!」一聲的樣板、章節字數區間。細節見 `fiction` 的 [`references/dialogue.md`](../fiction/references/dialogue.md) 與 [`references/structure.md`](../fiction/references/structure.md)。

## 這個流派靠你自己判斷的

- **線索公不公平**。讀者有沒有機會自己推出來,這是推理小說唯一的道德問題,程式判不了。
- **紅鯡魚是誤導還是欺騙**。差別在於回頭看時它說不說得通。
- **切章點**(斷頭台法則)。lint 量得出章有多長,量不出你停在哪一秒。

## 交稿前跑 lint

lint 在主層,本支不另外寫一份——武俠與科幻的規則檔會有 95% 相同,而重複的規則檔一定會分岔。安裝本 plugin 時主層會一起帶進來。

```
python3 skills/fiction/scripts/fiction_check.py 稿件.md --genre mystery
```

網路連載加 `--mode web`(段落上限收緊為 80 字且不超過 3 行)。
