# 要清掉的詞和句式

> 機讀版在 [`../assets/style_rules.json`](../assets/style_rules.json),由 `scripts/style_check.py` 執行。
> **要加詞、要調上限,改 JSON,不要改腳本,也不要只改這份文件。**兩邊不同步的話,以 JSON 為準。

分三類:硬禁(見一個清一個)、軟限(有配額)、在地化(陸味換台灣說法)。

---

## 一、硬禁

這些詞句一出現,讀者就知道是機器寫的,或者知道你在打官腔。lint 命中即 exit 1。

### 轉場與總結的萬用膠水

`值得注意的是` `值得一提的是` `不可否認` `毋庸置疑` `眾所周知` `綜上所述` `總的來說` `總而言之` `由此可見` `換言之` `一言以蔽之` `在一定程度上` `從某種程度上說`

這一整組的共同點:**刪掉之後句子完全不受影響**。它們存在的唯一功能是填充,讓段落看起來有結構。真正的轉場靠內容,不靠標籤(見 [`commentary.md`](commentary.md) 的「段落怎麼接」)。

> ✗ 值得注意的是,這家公司去年就虧了。
> ✓ 這家公司去年就虧了。

### 開場的罐頭

`近年來` `在當今社會` `當今時代` `在這個⋯⋯的時代` `隨著⋯⋯的發展` `在⋯⋯的背景下` `時代的浪潮` `歷史的必然`

寫下「近年來,隨著」四個字的那一刻,你就是在拖時間。開頭直接進場,背景邊走邊餵。

### 空心的評價語

`具有重要意義` `產生了深遠的影響` `起到了⋯⋯作用` `發揮了⋯⋯作用` `引發了廣泛關注` `引起熱議` `是⋯⋯的重要一環` `必由之路` `是一把雙刃劍` `敲響了警鐘`

這些片語沒有資訊。「產生了深遠的影響」——什麼影響?對誰?多深?講出來才叫評論。

> ✗ 這項改動對產業產生了深遠的影響。
> ✓ 這項改動之後,三家中小型供應商在半年內收掉了。

### 動詞被架空

`進行了` `予以` `加以` `深化` `打造` `助力`

中文的力氣在動詞。「對此進行了討論」的真正動詞是「討論」,被「進行了」架空成名詞。直接用動詞。

> ✗ 我們對這個問題進行了深入的研究。
> ✓ 這問題我研究過。

### 副詞疊床架屋

`極大地` `深刻地` `更好地` `全方位` `多維度` `深層次`

刪掉之後意思一樣,就是廢字。

### 管理黑話

`賦能` `抓手` `閉環` `顆粒度` `對標` `頂層設計` `底層邏輯` `生態位` `制度` `窗口`

`制度` 和 `窗口` 是使用者點名的兩個——它們是公文腔的代表,同時帶陸味。真的在談一部具體法規或一個具體單位時,**講那個東西的名字**,不要用抽象詞打發:

> ✗ 現行制度沒有給申訴留下窗口。
> ✓ 現行的《勞資爭議處理法》根本沒寫申訴要找誰。

真的必須引用原文(法條名稱、他人原話)而不得不出現這些詞,跑 lint 時用 `--allow 制度` 個案放行,並在稿子裡確認它確實在引號內。

### 把自己藏起來

`筆者` `本文` `我們可以看到` `不難發現` `可以說` `讓我們` `值得我們` `作為一名`

評論用第一人稱。細節在 [`voice.md`](voice.md)。

### 招牌句式

`不僅僅是⋯⋯更是⋯⋯`

這是 AI 中文最大的招牌。它的問題是把兩個東西並排,然後宣告後面那個比較深刻——但沒有論證。要講深刻的那一層,就直接講,不要用句式暗示。

### 句型殼

前面那幾組是「詞」,這組是「殼」——句子的骨架本身就是模板,換掉裡面的字也還是機器味。這類最難自己看出來,因為每一句單看都很通順。

**二元對比殼**:`不是 A,而是 B` / `並非 A,而是 B` / `不在於 A,而在於 B` / `與其說 A,不如說 B`

它擺出的是糾正的姿態:先否定一個沒人主張過的東西,再宣布正確答案。多數時候 A 根本是墊話。

> ✗ 這不是效率問題,而是系統問題。
> ✓ 問題出在系統上。效率只是最先被看見的那一段。

如果 A 跟 B 都真的重要,那就寫出它們的實際關係,別用「不是⋯⋯而是」把它壓成一句口號。

**易答殼**:`X 很簡單:` / `答案很簡單`

先宣告簡單,再給一個其實不簡單的答案。刪掉開場,把那個具體條件直接講出來。

> ✗ 這個問題很簡單:你的段落太整齊。
> ✓ 問題出在段落節奏。每一段都差不多長,讀者會先覺得順,再覺得假。

**本質殼**:`真正重要的是` / `核心在於`

把每個論點都升格成洞見,講久了就沒有一句是重的。直接講那個東西。

**流程殼**:`第一步⋯⋯第二步` / `先 A,再 B`

評論不是 SOP。順序真的會改變結果才留。`先⋯⋯再` 在口語裡很自然(「我先講結論,再回頭談過程」),所以它走軟限密度,不進硬禁——**誤報的代價比漏報高**,這是本表的取捨原則。

### 助理路標

`下面我們來` `接下來我會` `希望這能幫到你` `在這個過程中` `這背後其實`

聊天機器人的殘留物,它在報告自己接下來要做什麼。評論不需要導遊。

### 結尾互動問句

`你覺得呢` `是不是很有啟發` `你有沒有⋯⋯經歷` `不知道你怎麼看` `你卡在哪`

結尾向讀者討拍,是最廉價的收法。lint 另有一條動態判定:**最後一句是問號結尾、而且點名了讀者(你/妳/大家/各位)**,即算硬性違規。

不點名讀者的反詰不在此限,而且常常是好收尾:

> ✓ 這筆帳,最後誰在付?

## 二、軟限:有配額

這些詞本身沒問題,**密度高才有問題**。lint 用每千字上限計算,超過只警告,自己判斷。

抽象名詞:`機制` `維度` `層面` `本質上` `系統性` `結構性` `邏輯` `生態` `模式` `路徑` `面向`
連接詞:`因此` `然而` `從而` `進而` `首先` `其次` `進一步`
語氣填充:`其實` `事實上` `確實`
商業比喻:`賽道` `風口` `護城河` `天花板` `心智`
其他:`優化` `落地` `凸顯` `賦予`

共通的處理方式:一句裡出現兩個抽象名詞,通常代表你在描述一個你沒看清楚的東西。把它換成具體的人、事、數字,句子會自己變短。

> ✗ 這個機制在執行層面存在結構性的問題。
> ✓ 這規則寫得很漂亮,但第一線根本沒人力執行。

## 三、在地化:陸味換台灣說法

模型的中文語料以簡體為大宗,轉繁體之後詞還是陸的。這是「讀起來像 AI」最常被忽略的一半。

| 陸 | 台 |
|----|----|
| 質量(品質義) | 品質 |
| 視頻 | 影片 |
| 音頻 | 音訊 |
| 軟件 / 硬件 | 軟體 / 硬體 |
| 信息 | 資訊 |
| 網絡 | 網路 |
| 用戶 | 使用者 |
| 服務器 | 伺服器 |
| 內存 | 記憶體 |
| 屏幕 | 螢幕 |
| 打印 | 列印 |
| 博客 | 部落格 |
| 默認 | 預設 |
| 激活 | 啟用 |
| 高清 | 高畫質 |
| 智能 | 智慧 |
| 項目 | 專案 |
| 渠道 | 管道 / 通路 |
| 水平(程度義) | 水準 |
| 力度 | 強度 / 程度 |
| 通過(表方式) | 透過 |
| 立馬 | 馬上 |
| 接地氣 | 貼近現實 |
| 說白了 | 講白了 |
| 劃重點 | 畫重點 |
| 靠譜 | 可靠 / 有譜 |
| 貓膩 | 蹊蹺 / 有鬼 |
| 高大上 | 體面 / 派頭十足 |
| 走心 | 用心 |

lint 命中在地化詞會警告並直接給替換建議。有些詞在台灣科技圈已經混用(像「優化」),所以放在軟限而不是這張表——這張表只收替換後幾乎不會有歧義的。

## 生造的帶勁口語

**這一條是實測抓出來的。** 一個 agent 照本 skill 寫出的稿子,兩處被使用者一眼指為 AI 味:

| 它寫的 | 改成 |
|---|---|
| 我知道**最硬的**反駁在哪裡 | 我知道反駁的**重點**在哪裡 |
| 還有一件事**我想講死** | 還有**最重要的是** |

兩句的病一樣:**為了顯得像人,生造一個帶勁的說法來標示重點**。「最硬的」「講死」
聽起來有力道,但沒有人在講話時會這樣說——真人就是說「重點」「最重要的」。

這比公文腔更難抓,因為它偽裝成口語,而本 skill 要的正是口語。差別在於:
**真的口語是省力的,生造的口語是費力的**。「最硬的反駁」比「主要的反駁」多花了力氣,
而那份力氣讀得出來。

常見形狀(不限於):

- **生造強度形容**:最硬的、最狠的、最痛的、最要命的(當成「主要的/關鍵的」在用時)
- **生造動詞加碼**:講死、說死、講穿、講爆、寫死(當成「講清楚」在用時)
判準不是這幾個詞本身,是**它有沒有在替一個平常說法加戲**。
「這個反駁很硬」是評價,可以留;「最硬的反駁」把「主要的」換成表演,拿掉。

**宣告句式本身不是病。** 我一度把「我知道 X 在哪裡」也列進來,結果它誤殺了使用者
親自給的正確版本——使用者把「我知道**最硬的**反駁在哪裡」改成「我知道**反駁的重點**
在哪裡」,**保留了整個宣告框架**,只換掉那個生造的強度詞。這條已撤除。
留下來的教訓:抓錯層次的規則會擋掉正確的寫法,而那比漏抓更傷(KN-002)。

### 這一條腳本判不準,斷言只抓最有把握的形狀

使用者實測指出兩類**合法用法**,初版規則會誤殺:

| 合法句 | 為什麼合法 |
|---|---|
| 鑽石是自然界**最硬的**礦物 | 物性比較,「硬」是字面義 |
| 他不想把話**講死** / 不想講這麼**死** | 台灣口語本來就這樣講,意思是「不留餘地」 |
| 這件事還不能**說死** | 同上 |

所以斷言收窄成兩個高把握形狀:

- `最X的` **必須接論述性名詞**(反駁/論點/理由/證據/批評⋯)才算。修飾物體一律放行。
- `講死` **只抓「想/要 + 講死」**,且前面不是「話」。「把話講死」「講這麼死」不抓。

**收窄之後必然漏抓**——生造口語的形狀是無窮的,regex 只擋得住最典型那幾個。
剩下的靠人讀:問一句「**這個說法有沒有在替一個平常的詞加戲**」。
有,就換回平常的說法。這一半沒有機器在管,照 KN-001 的第二條路明講,不假裝有斷言。

**小說不受這條管。** 小說走 `fiction_check.py`,規則檔不同;對話裡出現
「不想把話講死」是角色在說話,本條完全不適用。不要拿評論的尺去量小說(KN-003)。

lint 收在軟限(`soft_limits`),不列硬禁——硬禁會製造 KN-002 說的那種誤報。
