# 改稿:把已經寫好的稿子去 AI 味

> 從零寫評論看 [`commentary.md`](commentary.md);詞句清單看 [`ai-tells.md`](ai-tells.md)。這份管的是**已經有一篇稿子了,要把機器味拿掉**。

寫作跟改稿的判準不一樣,別混。寫作時我叫你敢講死、要有角度;改稿時你**沒有資格換掉作者的判斷**。第一原則就是這個。

## 保存優先

改稿只能拿掉東西、換掉說法,不能加東西。

- **不編造**。不加事實、數據、例子、笑話、個人經歷。稿子裡沒有的,改完之後也不能有。作者寫「我去年遇過一次」,你不能幫他補成「我去年三月在台中遇過一次」。
- **不換立場**。作者的判斷、傾向、火氣、猶豫,全部留著。他寫得偏,那是他的選擇。
- **不補證據**。看到沒有支撐的主張,**把它講得弱一點**(「我猜」「看起來像」),不要去找一個來源塞進去。
- **不升格**。原文是隨手記的想法,就別改成社論。語域本身是稿子的一部分。

改完之後作者讀不出這是自己寫的,那你改壞了。

## 掃描順序

由大到小。反過來會白做工——先把詞換漂亮,結果整段要重寫,前面全丟掉。

1. **結構**:每段是不是同一個形狀(主張 + 解釋 + 小結)?段落是不是一樣重?是在列點還是在論證?
2. **聲音**:有沒有助理路標(「下面我們來」)?有沒有把自己藏起來(「筆者」「本文」)?是不是整篇都在對「你」講話?
3. **句型殼**:二元對比、易答殼、本質殼、流程殼——見 `ai-tells.md`。
4. **詞**:硬禁詞、軟限密度、陸味用語。
5. **結尾**:有沒有總結?有沒有向讀者討拍的問句?

跑 `style_check.py` 可以把 3、4、5 掃出來,加上段落節奏。1 跟 2 得自己讀。

## 局部改還是整段重寫

預設**局部改**,動最少的字。

只有一種情況該整段重寫:**AI 味來自這段的結構本身**。比如整段是「宣告主題 → 三個並列理由 → 回扣主題」,換詞救不了,骨架就是模板。這時重寫,但保留這段原本承載的每一個資訊點。

判斷方法:把這段的骨架抽出來寫成一句話。那句話如果是「作者在講 X 這件事」,局部改就好;如果是「作者在示範一個段落應該長什麼樣」,重寫。

## 什麼時候該留著殼

規則有例外,硬套會改壞。以下保留:

- **引號裡的原話**。別人怎麼講就怎麼引,包含他的官腔。引用法條、公告、財報用語同理——這時跑 lint 用 `--allow` 個案放行。
- **順序真的會改變結果**。「先關電源,再拆機殼」不是流程殼,是安全順序。
- **對比真的存在**。「不是 A,而是 B」在 A 曾經被明確主張過的時候,是有效的反駁,不是假糾正。差別只在:A 有沒有人真的講過。
- **重複是作者的口頭禪**。有些詞他每篇都用,那是聲音,不是贅字。

拿不準的時候問自己:拿掉它,讀者會不會少知道一件事?會的話就留。

## 輸出

**預設只給改後的稿子。**不要附說明、不要條列改了什麼、不要在文末寫「以上是修改建議」。

使用者明確要對照、要診斷、要理由時,才另外給。給的時候用「原句 → 改句 → 為什麼」三欄,不要寫成報告。

改完跑一次 lint,硬性違規清乾淨;軟性提醒逐條看,不是每條都要動。

## 交稿前

- [ ] 沒有加進原稿沒有的事實
- [ ] 作者的判斷跟語氣還在
- [ ] 硬性違規清空(引用原文的用 `--allow` 放行,並確認它確實在引號內)
- [ ] 段落有輕重,不是一樣長
- [ ] 結尾不是總結,也不是討拍
- [ ] 讀一遍:這還像原作者寫的嗎
