# architecture — 架構說明 / 設計文件

> 判定邏輯在 **`techdoc` 引擎**。本支管的是這個文體怎麼寫,以及該用哪個旗標。

## 核心

闡述系統的整體結構、模組關係、設計邏輯與**技術選型的原因**。

價值不在「我們做了什麼」,在**「為什麼不是另一個做法」**。手法:圖文互補(拓撲圖 / UML)、由大到小的邏輯遞進、Trade-off 分析。

**修辭比例**:極低(0%-2%),**僅允許類比**

## lint 會擋的(硬性違規,exit 1)

- **沒有任何圖 → 擋**。認 mermaid 區塊、markdown 圖片、ASCII 方框三種;認不出的畫法用 `--allow-no-diagram`,而那個旗標會被印出來——放行要留痕
- 模糊形容詞、誇張詞 → 硬性違規(與規格書同一組)
- 類比 → **配額 2 處**,且只能把抽象架構比成讀者已知的實物(微服務像積木)

## lint 會提醒的

找不到權衡 / 取捨 / 決策的段落

## 靠你自己判斷的(lint 判不了,明說)

- **圖畫得對不對**。lint 只確認有圖;依賴方向畫反了它看不出來——那正是圖要給人看的原因。
- **由大到小的遞進**。整體結構 → 模組關係 → 資料流 → 已知限制,順序對不對只有讀的人知道。

## 交稿前跑 lint

lint 不在本支——`techdoc` 引擎的同一份規則檔服務多個前門,拆成多份會分岔。安裝本 plugin 時引擎會一起帶進來。

```
python3 skills/techdoc/scripts/techdoc_check.py 稿件.md --kind arch
```

引述他人原文而不得不出現禁用詞時,加 `--allow 詞1,詞2` 個案放行。

完整規範見 [`references/architecture.md`](../techdoc/references/architecture.md)。
