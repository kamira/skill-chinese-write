# spec — 規格書

> 判定邏輯在 **`techdoc` 引擎**。本支管的是這個文體怎麼寫,以及該用哪個旗標。

## 核心

定義產品、系統或工程的技術參數、功能需求與驗收標準。唯一目的是**驗收那天指得出過或沒過**。

手法:模組化條列(1.1 / 1.1.1)、主動語態與絕對動詞(必須 / 應該 / 不可)、量化描述——**拒絕模糊形容詞,一律改用具體數據**。

**修辭比例**:**0%**,嚴禁任何修辭

## lint 會擋的(硬性違規,exit 1)

- 模糊形容詞(快速 / 良好 / 適當 / 盡量 / 大幅 / 顯著)→ **硬性違規**
- 誇張與情緒詞(非常 / 完美 / 革命性)→ **硬性違規**
- 譬喻 → **配額 0 處**

## lint 會提醒的

缺模組化編號;條列中含絕對動詞低於 30%

## 靠你自己判斷的(lint 判不了,明說)

- **量化描述夠不夠**。lint 抓得到「快速」,抓不到「回應時間必須合乎預期」——沒有模糊詞,也沒有數字。
- **邊界寫了沒有**。一份沒有「本規格不涵蓋」的規格,驗收時誰都可以說「這也應該要有」。

## 交稿前跑 lint

lint 不在本支——`techdoc` 引擎的同一份規則檔服務多個前門,拆成多份會分岔。安裝本 plugin 時引擎會一起帶進來。

```
python3 skills/techdoc/scripts/techdoc_check.py 稿件.md --kind spec
```

引述他人原文而不得不出現禁用詞時,加 `--allow 詞1,詞2` 個案放行。

完整規範見 [`references/spec.md`](../techdoc/references/spec.md)。
